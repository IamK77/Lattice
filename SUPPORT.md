# Getting help

- **Setup and use:** start with the [getting-started guide](docs/guides/getting-started.md)
  ([简体中文](docs/guides/getting-started.zh-CN.md)). Ask general questions in
  [Discussions](https://github.com/IamK77/Lattice/discussions).
- **Installation, upgrade, or startup trouble:** follow [installation](docs/guides/installation.md)
  ([中文](docs/guides/installation.zh-CN.md)) and [troubleshooting](docs/guides/troubleshooting.md)
  ([中文](docs/guides/troubleshooting.zh-CN.md)) before collecting a report.
- **A reproducible defect:** use the [bug report form](https://github.com/IamK77/Lattice/issues/new?template=bug_report.yml).
- **A capability or workflow improvement:** use the
  [feature request form](https://github.com/IamK77/Lattice/issues/new?template=feature_request.yml).
- **A security concern:** follow [SECURITY.md](SECURITY.md), not a public issue.
- **Contributing code or documentation:** read [CONTRIBUTING.md](CONTRIBUTING.md).

Search existing reports first. Include the output of `lattice --version`, your
operating system and architecture, the feature or step that failed, and the
smallest reproduction you can share. You do not need to identify an internal
component; name an optional integration if you know it. Say which steps you
tried and what you expected.
Use synthetic data. Do not upload an entire ledger, dump your environment, or
paste credentials. Review screenshots and configuration excerpts for secrets.

Support is community-based and best-effort. There is no guaranteed response time
or commercial support entitlement. Labels such as `help wanted` and `good first
issue` are applied after triage, not automatically to every new report.
