# 后台工作的短引用

后台列表、通知、工具回执和模型材料共用一套短引用。默认是八位小写十六进制字符，类型单独显示：Expert 是一次专家调用，Run 是一次后台命令，Timer 和 Watch 是一次订阅，不是专家定义、命令文本或路径的名字。

例如 `Timer e6d4a92b; stream="example"` 表示 example 流中的一次定时器订阅。示例编号不是实际任务。所属流始终是引用的一部分；八位字符不承诺全球唯一。后台列表显示所属流，完整的原始编号和创建事件仍在流水及原有工具结果中。

## 使用已有操作

在拥有该工作的当前流中，直接把显示的完整短引用交给原有工具：

```json
{"tool":"Unschedule","arguments":{"timer":"e6d4a92b"}}
{"tool":"Unwatch","arguments":{"watch":"82ac5f17"}}
{"tool":"CancelExpert","arguments":{"job":"a7c92e04","reason":"需求改变"}}
```

这些仅为参数示例，不会授予权限。通过 `UseDeferredTool` 调用时规则相同。原有数字参数仍有效，例如 `{"timer":1}`；字符串始终按短引用精确查找，即使它全是数字，也不会转成旧编号。不接受任意前缀、截短、未知引用或其他种类的引用。当前流之外的引用不能借此操作另一条流。

Run 没有因这项功能而新增取消或返回前台操作，后台面板也没有新增取消按钮。

## 身份、碰撞与恢复

身份包含所属流、工作种类、有类型的原始编号以及实际创建请求的事件编号。数字 `1` 与字符串 `"1"` 不同；同一个提供方编号重用后，也不是同一次工作。经过关卡转发时，创建请求是提供方实际收到的那一份，历史归卡则沿同一次请求的转发关系找到原卡。

散列输入是带版本标记的规范 JSON 元组，算法为 SHA-256。每条流的四种工作共用一个名称空间。投影按流水中首次出现身份证据的顺序分配短引用；遇到碰撞只延长新引用，不改已经显示过的引用。已结束工作的分配仍然保留，排序、状态变化、清屏和重开不会回收编号。

这不是一个新身份服务。列表、模型材料和操作解析使用同一个可重建的流水投影；检查点只加速恢复，不改流水，也不重新执行工作。旧流按相同规则获得短引用。读不出依据就报告错误，不把读取失败当成“没有任务”。没有足够因果依据的旧显示保留原始文字，不猜测同编号的某个实例。

操作解析和模型材料构建不依赖派生检查点成功写盘。已从流水重建出有效身份后，若仅缓存文件写入失败，继续使用内存里的结果，并通过现有标准错误诊断路径报告缓存发布失败（终端全屏时该路径写入诊断文件）。这不吞掉正本错误：恢复、身份核对、保存前的流水前缀读取仍须成功；读不出流水或保存边界无效时照常报错。直接要求保存检查点的原有严格接口也保持不变。

## 操作与显示的边界

主循环在原有授权链之前，把已知短引用解析为原始数字参数，同时保留目标创建身份。授权关卡仍审查原有操作及参数；引用不是授权。未知或不匹配的引用仍经原有工具结果路径返回一次错误，不留下悬空调用。

随货的定时器、文件监控和专家服务在执行前，用自己的运行中实例核对创建身份。这道核对不读取父进程历史，所以工具运行在子进程中也成立。自定义提供方不会因为收到这份附加数据而自动具备同样的核对逻辑。

迟到的旧回执不能替换较新的后台条目，即使新条目已经结束；旧通知和旧操作不能修改复用同一数字编号的新条目。历史命令卡先按请求因果关系归属，再显示引用，不能把旧输出贴到新命令上。工具原始输出、图像附件、精简回执和摘要仍沿原有呈现路径保留。

本功能不改变后台工作的执行方式，不扩大停止保证，也不修复独立的取消/恢复问题 #123。旧数字参数的既有取消语义保持不变。代码验证与人工界面验收分开记录；合入开发分支不表示已经安装或发布。
