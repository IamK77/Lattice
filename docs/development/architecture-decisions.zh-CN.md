# 架构决策

本文解释当前各子系统的机制与理由。整体心智模型见《架构总览》，字段与协议以 `schemas/` 和 `docs/contracts/` 为准，贡献约束见 `CLAUDE.md`。

## 装配与部件

装配是一份显式接线的数据说明书。部件声明事件口、工具、提示片段及默认接线建议；说明书决定实例、配置和全部连接。内核不根据工具名猜接线，也不绑定实现语言。进程外部件通过标准输入、标准输出交换逐行 JSON；这不是 HTTP 协议。

产品装配由完整基线与安装增补组成。`LATTICE_ASSEMBLY` 选择完整基线，选定文件坏了就拒绝启动；`lattice assembly` 导出基线，不把增补混成基础实例。当前聊天宿主要求 `model`、`cmodel`、`ctx` 三个运行时位置，模型选择与上下文设置由宿主填入，接线仍由基线明确给出。这些角色约束不进入核心契约。

`~/.lattice/assembly.json` 是只增不改的安装记录，`LATTICE_OVERLAY` 可更改路径或禁用。它不能覆盖基础实例或删除基础接线；增补合并失败会告警并跳过。安装后的接线参考同类实例，但授权关卡不能被当作普通工具同伴而绕开。卸载只管理运行时确认为安装所得的实例，不相信后来修改的文件自行宣称的归属。完整基线与安装增补不可共用文件，具体使用见《装配配置》。

口型是部件的结构与行为约定：自述用 `implements` 声明，实例用 `requires` 要求；体检检查事件口，符合性检查检验行为。结构相同不代替明确声明。正式口型见 `docs/contracts/05-standard-interfaces.zh-CN.md`。

## 内核与执行

每个部件有邮箱与执行线程，阻塞处理不占用其他部件的线程。外部注入绑定实例身份并唤醒宿主。观察者队列有界，溢出后从持久流水按序补读。主循环的派发上限防止坏部件无限活锁，不禁止合法的环形接线。

落账先于投递，信封、事件口、因果见证与信纸分别校验。流水写盘失败必须停止；部件崩溃、超时与坏发射则通过控制事件报告，不连带杀死其他部件。重启时只为没有结局的调用补 `interrupted`，不重新执行它们；中断不能被解释成“确认没有生效”。

处理计时从取得工作槽开始，不把排队时间偷算为处理预算。邮箱暂时没有消息不表示轮次完成；尚有工作时，停滞诊断不能把宿主提前交回空闲状态。真正到期仍走取消与失联处理。

进程桥独立负责创建、协议、取消和回收，生命周期决定仍属宿主。桥独占子进程退出状态的收取；登记锁内完成信号与登记撤销，锁外等待子进程和读取线程。旧桥按名字和编号核对登记，不删除同名新实例。握手失败由创建者清理尚未登记的子进程。管道关闭不等于子进程退出，进程隔离也不等于沙箱；逃离进程组的后代不在回收保证内。

## 审计、存储与恢复

流水是持久正本。模型材料以事件指针和指纹表示，由适配件实体化；每次请求仍记录完整材料清单，因此不承诺整本流水随对话线性增长。压缩、摘要、渲染缓存和恢复检查点都是视图，不能改写历史。

分卷启动校验索引与当前卷，封存正文按需校验，全量验证由用户显式运行。因此未读旧卷的损坏不保证在启动时发现；读取错误绝不能被当作记录不存在。派生缓存损坏不得取代正本，也不能导致历史操作重新执行。

终端主会话的“新建”必须把创建意图带到存储入口，不能先探读同名流水的身份再走普通打开。核心只提供中性的独占创建入口：仅接受非空的 `.ledger` 路径，装配和信纸校验通过后直接创建目录，并把同一份写入占用权一直交到停机后的最后一次记录写完。候选名沿用现有规则；名字被占用就明确失败，不自动换名、不收养旧流水、不删除失败后留下的证据。创建失败报告候选路径与原始原因，提醒可能留有部分初始化内容；不能把后续步骤的同名错误也说成候选冲突。配置引导取消仍不分配流水，继续会话仍沿用引导前选定的目标；新建成功后界面身份取实际运行的流，历史回放边界为零，不等于启动流水没有事件。普通打开、页签和其他宿主的既有语义不随这个入口改变。

历史查询优先在已有读视图中做窄扫描，不为一个问题深拷贝整本流水。需要沿因果查询时使用同一读视图，不依赖可重入读锁。前端与恢复逻辑共享历史，仍不代表全部进程状态或材料列表已经有界。

## 模型适配与上下文

主循环等待的是自己发起的具体模型调用，不是一个笼统的“正在等待”标志。发射时事件编号尚未分配，因此用实例身份、发射前的流水边界和完整原因清单定位请求；关卡可以改写请求正文，所以正文不能充当身份。沿同类请求查找转发链，是否结清仍复用契约的按序判定，不把其他事件引发的新请求当成副本。一次结局只消费一次；迟到的完成或打断保留在审计里，但不能再次回复、启动工具、清掉下一次等待或混入后续材料。含有工具目标的混合打断仍须处理工具部分。

历史材料重建也过滤重复的模型结局，不能只在实时执行处拦住它。接纳条件是“本实例发起的原始调用被这条结局结清”，不是“任意转发副本被结清”；同一原始请求分出的其他支路仍按共享契约保留未结束状态，但它们的迟到结果不能重新混入已经结束的主循环材料。其他主循环的模型结局同样不因重启而改变归属。材料检查点按实例分别保存，并同时记录尚未结清的调用关系与本实例的原始调用清单；读到归属不符的缓存就重新派生。这只是材料投影，不恢复正在执行的工作。旧版无归属检查点重新派生，页损坏修复沿用相同的实例归属与过滤，且不收进尚未投递给主循环的新输入。流水正本和事件契约不因此改写。

模型配置分成三份：适配件决定方言，目录决定端点与密钥变量，档案决定上下文窗口、思考档位及用量字段。二进制不附送可达模型条目；用户必须配置自己的目录，档案则可以随货。换模型是更换实例与配置，保留它原有的接线和历史材料。

本地档案的 `systemPromptSupplement` 由用户写，随货档案不附送内容。取值跟着实际选中的目录条目走；同一连接但有效档案不同，仍是一次有效切换。公共提示词先完成模板替换，再原样追加补充；上游显式系统提示词只替代公共部分，不进入后续普通请求的公共缓存。部件说明的刷新仍可等缓存变冷，条目切换与本地重新加载的补充变化则不能等：转发请求记录内容指纹 `contextSystemProfile`，只用于判断旧公共提示词能否复用，不交给供应商，也不在元数据里复制补充原文。补充为空时不加此字段。重开时以新装配读取的本地值为准，不用历史切换事件中的旧文字覆盖；实时切换显式传空值以移除补充。保留条目身份也用于列表标记和删除保护，不能因为本地档案改了、当前配置被显示成临时行，就允许删除实际使用的目录条目。文本纪要不继承普通补充；原生压缩保留被压缩请求已有的完整系统提示词，手动压缩的参照仍是最后一次已转发请求。

Rust 组装调用者需要迁移两处源码：`PresetConfig` 的结构体字面量新增 `entry_id`，没有目录身份时填 `None`、沿用按型号命名的回退；`preset::model_profile` 现在返回 `Result`，调用方需要传播或处理配置错误。旧序列化配置缺少 `entry_id` 仍可读取，不需要修改已有 `models.json`。

首次配置由终端前端在创建会话之前完成，不增加运行时启动框架。提供商只是地址与格式的预设，不是型号，也不是新的核心概念。引导维护未保存草稿；返回保留输入，地址、格式、账号、型号变化则使依赖资料失效。同一型号重新获取资料，只覆盖尚未手动修改的字段。模型列表与能力资料分开处理：列表不能证明所有接口或工具都可用；能力建议必须标来源、允许修改，未知图像能力保持关闭。服务只报告输入上限时，不加上输出冒充总容量，而将其标为保守预算供确认。列表获取与短请求测试都需明确选择，记在目录旁的独立记录中，不伪造聊天轮次，也不自动重试或跟随重定向。

配置引导的语言只属于前端，不改变主界面、模型配置或流水。文案以稳定标识集中管理，变量只替换一次，服务原始诊断与本地解释分开。语言优先级为明确保存的选择、终端语言、英文；自动判断不写偏好，明确切换使用既有安全写入器，失败只影响记忆、不阻止本次切换。正常配置采用 Lattice 选定的默认连接、自动建议名称，一份总览负责确认；资料完整时不再逐项追问。返回保留已提交草稿，未提交输入不算完成；从总览打开的编辑记录入口，取消回总览，不能与顺序后退混用。缺少有效地址时不能进入后续连接步骤，最终保存仍检查容量关系。新建和只修密钥分别持有草稿，后者不借修复重写未知字段或能力档案。

配置引导使用独立的临时终端屏幕，每个任务替换上一页，而不是把问答当成不断追加的日志。单个输入控件仍由 inquire 管理，外层负责页头、摘要、长说明分页和屏幕生命周期；退出不清除原屏幕，交给主界面前必须先释放引导屏幕，二者不能重叠持有。总览只显示主要信息，完整配置和来源按需展开；重试错误替换上一份，不改变明确联网、草稿或落盘的边界。布局在问题和详情页切换时重算，不承诺输入控件阻塞期间即时响应缩放。同步网络请求期间重新保持终端原始输入模式，让取消键留作输入、避免进程被信号直接终止；取消在有界请求结束后处理，不能宣称立即中止网络请求。普通返回与可展开的异常由外层恢复终端，不把强制终止或进程崩溃纳入保证。待显示的安全诊断只在页面完整写出并刷新成功后才清除；窗口尺寸检查、分页或绘制失败都不能提前消耗它。退出时先尝试恢复终端，再把未显示的诊断与引导失败一起交给普通错误出口；恢复失败也须保留原始错误。正常结束或取消时，仍未显示的提示在恢复后输出；回退输出本身失败则把提示随错误继续返回。不重发网络请求、不改配置或请求记录，也不承诺已经失效的输出设备必然能显示文字。

密钥可由目录中的 `apiKeyEnv` 引用，也可直接写 `apiKey`。后者会被转存为进程环境变量，适配件配置与换模型事件只携带变量名；但目录本身仍可能被工具读取，不能据此宣传密钥不会进模型上下文。读坏的目录不得被当作空目录覆盖，当前使用条目不可删除。界面目录变更记前端自己的事件，不给核心新增“模型目录”概念。

适配件内部只对规定的发送阶段传输失败重试；成功取得 HTTP 响应后，读回复中断不重发。重试等待可取消，最终只交一份结果。已经落账的失败由模型决定下一步，运行时不暗中循环重试。Responses 普通请求的缓存分组键来自流身份，不依赖每次调用或提示内容；仅在适用的入口发送，不保证服务端缓存命中。向导与运行时共用已识别入口的鉴权和选填参数差异，不因接口同名就照搬另一家的字段；这些差异不进入核心或事件契约。

共享流解析保留现有的逐行约定：LF/CRLF 结束一行，每条 `data:` 行独立解析 JSON，不拼接多行 JSON，也不扩大为完整 SSE 协议实现。已知 `[DONE]` 标记继续跳过，合法的未知事件与元数据继续由原规则忽略；坏 JSON、非法 UTF-8、正常 HTTP 结束时残留的未结束行必须明确报错，不交出工具调用。Messages 与 Chat 保留已经收到的文字、用量和推理，Responses 不新增增量文字持久化。取消与传输中断不冒充正常结束，不拿残行检查覆盖原有结局。

解析结果必须按顺序逐条交给适配件，不能先检查整块网络数据再决定是否交出前面的内容：否则同块尾部的错误会吞掉正常前缀，或者让已完成的 Responses 被后续垃圾推翻，结果随网络如何分块而变化。Messages 与 Chat 仍读到 HTTP 结束，Responses 仍在自己的终结事件处返回，`[DONE]` 不替代这些完成条件。本次不增加读取超时或未经端点约束确认的大小上限；未结束行的缓存仍可能增长，不将此修复称作资源隔离。

Messages 工具参数解析失败不能改成空对象继续执行。起始 `input` 必须是对象，与后续 JSON 字符串分开保存；没有增量或只有空字符串增量时保留起始对象，非空增量拼接后单独解析，不与起始对象合并。这选择保留原始信息，与 Python SDK 的处理一致，不声称所有 SDK 在空增量边界上相同。工具块正常结束、整条消息以工具调用原因正常结束后才交出调用；任一工具的参数、标识或完成边界有错，整次调用报错，不交出其余工具，已有文字、用量与推理仍保留。取消、传输中断和输出截断继续走原有结局。这是对已解码事件的校验，不代替共用流解析器的外层帧校验。

上下文闸负责材料注入、预算、取舍与摆放。语义压缩失败会暂停自动压缩，普通对话和机械裁剪继续；失败不会因下一轮或重启自动消失。`/compact` 是一次明确的新尝试，只有成功且产物被采纳才能解除暂停。因输出上限被截断的摘要不能仅凭标题齐全而采纳。新模型配置与旧配置迟到的结果必须分代处理。

供应商原生压缩不继承普通思考开关；模型生成文本纪要才请求关闭思考，未声明关闭能力的兼容入口会提示采用服务默认行为，不能承诺已经关闭。支持 Responses 本身不代表支持 Codex 触发式原生压缩：已识别的兼容服务使用普通文字纪要，原生及既有自定义网关暂保留原压缩行为。推理与其工具调用按完整事件共同保留，跨方言不替供应商伪造签名。新支持的兼容 Messages 入口只回传真实存在的思考块，不继承旧端点要求的空块占位；保留原生 Anthropic 与 DeepSeek 的既有行为。具体表示及端点兼容限制见《核心事件类型》。

Responses 的“允许新搜索”与“能接收历史搜索记录”是两件事。普通聊天仍由档案的 `nativeWebSearch` 决定是否声明供应商托管搜索；触发式原生压缩（`context.compact.responses` + `compactionProtocol=trigger`）则检查实体化后的顶层输入。若含 `web_search_call`，即使当前档案已关闭搜索，也须声明一个 `web_search` 工具，否则已实测的端点会拒绝这段历史。该声明只补请求的能力说明，不删历史、不改加密内容，也不索取搜索来源字段；已有声明保留第一份及其选项，同名本地函数不算托管声明。这不是远端不联网的安全承诺。文本摘要与旧式 `/responses/compact` 请求保持原行为，无历史搜索的触发式压缩也不补声明。

## 工具、证据与授权

工具结果是审计事实，不等于模型必须每次重收全部原文。成功结果可以显式提供简短 `modelText`，适配件标明省略并给出原事件编号；完整结果仍留在流水，错误和取消不能用成功摘要代替。图片用内容寻址的文档引用，不把大段 base64 写入每行一条的流水；发送前验证身份、字节数及 PNG 内容，坏图不能静默丢弃。

Run 保存标准输出和错误输出，内存只留有界首尾窗口。普通长命令可自动交给后台并返回等待回执；`background=true` 表示立即继续独立工作。成功启动不等于命令成功，后续完成通过唤醒报告，不能对同一工具调用补第二份结果。交接后的命令不会因对话取消自动结束；重启只清账，不重跑。管道继承导致输出无法结束时，有限宽限后封存已捕获部分并标为不完整，不无限等候。

Read 的版本校验基于受限大小的字节快照，范围回执绑定文件版本和返回内容。`knownRead` 只在调用方仍持有旧内容时使用；丢失上下文就重新读正文。搜索分页绑定查询及目录元数据，不承诺内容事务快照；Fetch 保留来源与完整可得证据，并说明下载或预览截断。

代码导航调用本机语言服务，不用文字搜索冒充定义或引用。语言服务可能构建、执行插件、写索引或联网，不能按只读文件工具授权。文件哈希不证明服务索引新鲜，查询前同步文件并核对版本，仍不承诺全工作区原子快照。

随货信任闸按参数指纹与申报作用面判断。URL 内容或本地路径内容后来改变，不会因此重新授权；永久信任的撤销仍由用户手动管理。作用面由工具自己声明，范围字符串没有沙箱执法，所以这是防误操作机制，不是恶意代码隔离。安装、浏览器和桌面内容也不能自行授予权限。

操作授权另有两个寿命：本流授权存入流水，重开保留并可逐项撤销；界面临时权限只在当前绑定寿命内有效，关闭或重开即失效。两者都不能偷偷变成永久信任。只有模型实际消费的工作输入贡献界面权限，多个来源取任一仍有效者；旁观者、未消费的插话和跨流弱引用不算来源，后台工作追溯创建者而非最近发言者。

操作关卡检查精确参数前缀，组合命令全部通过后仍执行原脚本；不能可靠解析就整体审查，不靠子串猜安全。规则优先级为禁止、询问、允许，临时界面权限只能省去询问，不能越过禁止或服务本身的版本、参数与执行校验。关卡、临时权限服务和原有信任服务分别负责决定、活状态和永久记录，宿主仅管理绑定身份，内核不增加授权分支。消费者读到权限服务失效或新运行期记录时，不再使用旧开启快照；这是已经入账的失效，不是对尚未发现的故障作存活保证。详见《设计-操作授权》。

脱敏在聊天事件落账时执行，早于持久化与订阅。它只认宿主启动时交给它的具体值，不猜“长得像密钥”的文字；工具请求与结果不在范围内，运行期取得的新秘密也不会自动加入。因此工具读取配置或环境时，秘密可能原样进入持久流水和模型上下文。

## 前端、支线与专家

后台工作的短引用由共享流水投影派生，不另建身份服务，也不替换执行编号。身份包含创建请求，已结束的分配仍保留；碰撞只延长新引用。操作先解析为原始参数再走现有授权链，提供方用本地实例核对创建身份。显示归属同样核对实例，不能让迟到回执或通知串到复用编号的新工作。规则与兼容边界见[后台工作的短引用](background-references.zh-CN.md)。

前端只在数据、输入或可见动画变化时重画。已完成文本按内容缓存渲染，正在增长的流式正文不进入整篇缓存。终端另保留可见页，并对已排版的显示组同时限制缓存字节量和组数：打字和动画不能反复还原不变的长工具组，流式片段只使可见页失效；已提交事件、折叠或宽度变化会使相关组重新排版。动画只更新明确标记的工具标题符号，不按文字内容猜测。输入布局、光标与上下移动共用屏幕行解释，软换行不改正文，控制字符不能原样驱动终端。工具卡片只折叠显示，不改请求、结果或历史；Write 正文只显示一次，Edit 使用写入时捕获的差异，不从当前文件反推历史。

终端把整轮结果放在同一个底部状态位置：正常结束为 `Done`，中断为 `Interrupted`，已有中断事件明确记为 `by=deadline` 才显示 `Timed out`，不按耗时或说明文字猜测。回复与轮次结束沿共同原因关联当前对话模型调用，并复用契约中的转发链结算规则；工具或辅助调用中断不结束整轮，旧结局不覆盖新的调用状态，空闲通知也不是成功完成的凭证。正文不合成 `[interrupted]`；已经显示但尚未提交的文字只转成本地显示卡片，不写入流水或恢复检查点，重新打开时不会凭空恢复。卡片和终端状态的旧派生缓存按版本重建，原流水不改。瞬时流式片段目前没有调用编号，因此这里不承诺识别新轮期间才送达的旧片段。

用量总数读供应商账务字段，构成按内容字节分摊，不冒充逐项分词。启动、关闭与轮次渲染各记录完成态观察，子阶段不能与父阶段重复相加，未成功到达观察终点就不生成成功汇总。全屏期间标准错误由终端宿主写入独立诊断文件，不塞进聊天。

支线是独立流，通过弱引用关联父流，只读摘录不赋予向父流发事件的权利。它也不是文件系统沙箱，各流工具仍可能操作同一目录。每条支线有自己的执行与界面状态，模型、授权和草稿不能互相覆盖；恢复索引读坏就报错，不把缺失记录当空白重建。

支线启动从拿到实际会话起就必须有人负责收尾：先交给尚未发布的本地所有者，再恢复界面；普通恢复错误显式停机并等待会话线程结束，原错误保留，停机失败或仍未退出的部件另行附加。异常展开和未被接收的成功结果由同一所有者兜底；诊断写不出去不能再制造一次异常。结果尚未入队就失去接收者，收尾发生在启动线程；已入队结果被丢弃则在丢弃者线程，不能承诺都在后台。索引保存失败仍走交互线程发起停机、退出界面后回收的既有路径，首条问题必须晚于索引提交。这一责任不延伸到尚未返回会话句柄的内部启动失败，也不新增全局退出时限或强制结束不配合的进程内代码的保证。

专家委托使用独立模板和空白上下文，不把裁剪后的主装配冒充专家模板。取消按父流及作业编号定位，取消回执与最终结局分开；先停止派发，再处理迟到结果和清账，结束后只报告一次。取消不回滚已发生的操作，不承诺不配合的进程内线程已经停止。专家委托不是任务图、优先级和仲裁调度层；完整调度层尚未提供。

自定义专家把可编辑定义、持久启用状态与单次委派快照分开。定义存在不等于获准使用；预检先核对版本并生成授权说明，信任闸批准后才提交启用状态。启用记录的原子替换是实际提交点，工具回执丢失不会使已经生效的状态倒退，也不能成为恢复时重做的理由。接受委派前捕获真实模型配置和装配，宿主不再按名称重查最新版。业务职责位于专家部件与产品宿主，核心没有专家钩子。终端管理面板与主 agent 共用管理及授权链，前端不直接写定义。检查和修改结果返回一份可接续操作的快照，避免重复正文与重复检查；这不取消后续请求的版本校验。契约、路径和验证边界见《设计-自定义专家执行》。

## 技能与桌面

技能是纯数据目录，核心不认识技能。`skill-consumer` 只负责发现、展开、加载和目录刷新，`skill-installer` 才负责安装；文件工具同样拆为 `fs-reader` 与 `fs-writer`。装配分别选择使用与修改能力，不保留旧的全能入口。探索和研究专家不装写入或安装部件，其工具目录也只列实际装入的声明。这限制随货工具提供的操作，不等于操作系统沙箱：模型联网、运行时落账和缓存仍在，读取也可能泄露数据。

安装成功时，安装部件发出已有的 WAKE 事件，只接到消费部件的刷新口，不接主循环输入，因此更新菜单不额外唤醒模型；常驻提示仍按缓存规则接纳。目录尚不存在也不依赖文件监控碰巧发现安装。恢复时消费部件重新扫描磁盘，不重做旧安装。用户呼出的技能由客户端路径展开，模型选择的技能按需加载。技能头部的 `allowed-tools` 不替代工具权限执法。自定义装配及进程入口须显式迁移，见[迁移说明（英文）](capability-split-migration.md)。

技能头部只按数据解析。YAML 解析器仅开启反序列化，不开启文件包含和变量展开；`${HOME}` 等保留为文字，未知标签直接报错。保留普通锚点与别名，但 `<<` 不自动合并字段。换掉停止维护的解析器后，重复键与非有限数改为报错，避免相互矛盾的元数据静默覆盖或变成空值；`true` / `false` 不区分大小写地成为布尔值，`yes` / `no` / `on` / `off` 保留为文字。保留解析器的深度及别名展开预算，不承诺整个技能文件的读取内存有硬上限。

桌面工具与平台驱动分离，当前 macOS 后端使用独立 Cua Driver。目标身份含进程出生信息和窗口身份，尺寸变化要求重新观察；批次先校验，再逐项执行，失败即停，不自动重放。完成计数只证明驱动调用结束，不保证界面目标达成。截图会进入持久记录并交给模型，系统权限仍由操作系统决定。安装与使用见《桌面操作》。

文件监控在 macOS 使用 kqueue，不依赖 FSEvents 注册；递归监控占用文件描述符，大目录可能报告资源不足。监控恢复是续订，不补发停机窗口内的变更；后台任务恢复也不重新执行旧操作。

## 发布版本与开发身份

正式版本放在 Cargo 清单里，不从提交数量推导。一个版本是维护者确认过的一组能力与兼容承诺，不是仓库的计数器；浅克隆、归档和不同合并路径不应改变它。Git 只提供开发构建的基线身份，开发版本必须与正式发布不同。发布构建显式确认清单版本，避免仅仅选择优化配置就冒充官方安装包。

提交使用通行的英文 Conventional Commits，历史自定义尾注不再参与版本计算。发布整理读取原始提交，排除合并提交；这样保留 Git Flow 的同一提交身份，不再靠把所有合并都标为 chore 来补偿计数。发布 PR 是审阅版本、变更记录与迁移说明的地方，合入 main 才确认发布；准备候选与实际发布分开。具体约定见[版本与变更记录](../maintenance/versioning.zh-CN.md)。

## 明确的限制

当前没有 WASM 沙箱或对任意工具的范围隔离。安装授权不检测同一 URL 内容漂移，安装、卸载和替换仍需进一步强化状态变更与审计失败的一致性；进程形态替换的先拆后建、注入器代际与锁中毒处理也不能被描述成已解决。长历史的内存与调试构建首屏性能不保证有固定上限。

清理内部过程资料不改变这些产品边界。使用者应在可接受的文件与网络权限环境中运行，并保留对审计、配置和凭证的管理责任。
