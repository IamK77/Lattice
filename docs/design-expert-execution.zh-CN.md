# 自定义专家：启用与执行后端

这是 issue #45 的第一批生产链路，不是完整管理界面的交付。此前的测试原型见《设计-自定义专家快照原型》。

## 三件不同的事

1. **定义**是可编辑的数据文件，说明专家的用途、常驻指令、模型目录名称和能力组。文件存在不代表获准使用。
2. **启用**是经过授权后，把某个具体版本标为可复用。持久记录另存于用户状态目录，带上原授权请求的账本、流和事件位置。
3. **委派快照**是在接受一次任务前，把实际模型配置、组件声明和装配接线完整捕获。后来的宿主直接消费它，不再按专家或模型名称查最新版。

核心不认识这些概念。业务数据、解析和管理工具属于专家部件及产品层；流水、授权、装配检查、子流生命周期仍用已有机制。

## 定义与来源

机器正本是 `schemas/expert_definition.json`。例如：

```json
{
  "v": 1,
  "id": "reviewer",
  "name": "Reviewer",
  "description": "Review source changes and report evidence",
  "instructions": "Read the requested source. Report findings with file paths and line numbers. Do not modify files.",
  "model": "your-existing-model-entry",
  "capabilities": ["read"]
}
```

- 项目来源：`<workspace>/.lattice/expert-definitions/reviewer.json`，名称为 `project:reviewer`。
- 个人来源：`<home>/.lattice/expert-definitions/reviewer.json`，名称为 `personal:reviewer`。
- 内置名称可显式写成 `builtin:explorer` 等；内置项不可通过定义管理修改。
- 项目身份同时绑定解析后的工作目录。同名短名称出现多个来源时拒绝猜测，要求明确来源。
- 若解析后的工作目录就是个人主目录，两种来源会指向同一文件。此时只提供个人来源，明确拒绝 `project:`，不把同一个文件当成两套锁和授权；旧项目身份也不自动迁移授权。列表返回 `projectAvailable=false`，终端新建或复制时选择个人范围。
- 标识符只允许小写 ASCII 字母起头，后续为小写字母、数字、连字符或下划线，最多 64 字节；正文文件上限 1 MiB。
- `approved`、密钥值、可执行入口和任意接线不是定义字段。格式损坏、未知字段、版本不支持都报错，不按空文件覆盖。

能力组对应随货部件：`read` 为文件读取和搜索，`write` 为文件写入和编辑，`web` 为抓取和搜索网页，`commands` 为命令执行，`skill-install` 为技能安装。基础对话及技能消费链仍存在。没有选中的修改或安装部件不会装入；这不是操作系统沙箱，模型网络、落账和缓存仍会发生。

## 现有入口

主 agent 可以先读取或编写候选数据，再调用：

1. `ListExperts` 查看来源、可用性与已有模型；`InspectExpert` 用带来源的名称读取一份快照：`definition`、`target`、`fileVersion`、`activation`、状态和不可用原因。正文及版本信息只返回一份，不再重复展开三套修改参数。
2. 修改请求复制快照的 `target` 和 `fileVersion`，把 `activation` 原样作为 `expectedActivation`，另加 `operation` 与非空 `reason`。`SaveExpert` 使用 `operation=put` 并带拟保存的 `definition`；`ActivateExpert` 使用 `operation=activate` 并带快照中的完整 `definition`；`DeleteExpert` 使用 `operation=delete`，不带正文。
3. 保存与激活返回 `details`，结构与检查结果一致，可直接接下一步，无需每次重新检查。激活回执里的详情来自锁内提交的同一份定义和新状态，不在提交后另读一次文件。任何后续冲突仍要求重新检查；回执不是免检查的通行证。
4. 人在现有授权交互中批准后，服务再次核对正文、文件版本和此前启用记录，成功才提交启用状态。保存不会自动激活；删除另走明确确认。
5. `ask` 不带专家名时发现条目，带专家名时解析已启用版本并接受委派。

`target.root` 是定义的保存来源，不能据此推断工具能访问哪些目录。`toolRoot` 单独报告专家文件工具的配置根目录；为 `null` 表示未配置这层目录限制，而不是操作系统权限或沙箱承诺。个人级定义不因此获得额外目录访问权限。

本轮调整了功能分支原型的工具回执：移除了 `activateArguments`、`putArguments`、`deleteArguments`；激活结果改为 `{activated, details}`。请求字段、授权规则和持久状态格式不变。自定义客户端应按上述快照字段构造下一步请求。

标准装配先经过 `expert-review` 做启用预检，再进入 `trust`。预检生成授权说明，包含来源目录、前后版本、模型、能力组和完整常驻指令；不接受调用方伪造的说明。授权判断仍按完整参数指纹及作用面进行。启用工具声明保守的最大作用面，说明中的能力组才描述本次选中的具体装配。

自定义完整装配不会自动获得这些接线；需显式配置定义服务与预检链。默认工具链现在是 `loop.run → expert-review.review → trust.review`，插入额外关卡时必须移除被替代的直连，不能保留旁路。

终端管理面板已接入同一条管理与授权链，支持编辑、复制和受控删除，操作路径见《演示-专家管理原型》。脚本测试不代替人工体验验收；Ink 尚无同等管理表单。

## 提交、冲突与恢复

启用记录位于 `<home>/.lattice/expert-activations/`，文件名由完整来源身份派生。它不是可编辑定义的一部分，也不把信任闸的可复用 grant 当成启用已经成功。

同一身份的托管写入者在稳定侧车文件上加锁，在锁内重新检查此前记录，写同目录临时文件、同步文件并原子替换。**原子替换是实际状态提交点。** 此后的工具回执如果丢失，调用结局可能是 `interrupted`，但已经生效的状态不会因此回滚；恢复只读记录及授权证据，不重新执行修改。

等待授权时定义发生变化，旧请求不能提交新正文。启用后手工修改正文，新版本重新进入待确认状态，不暗中退回旧版。格式化不改变语义版本，但会改变修改冲突使用的精确字节版本。

这些锁只约束参与协议的写入者，不约束任意外部程序。此机制防误操作，不是对能够修改本机信任文件或流水的恶意进程提供隔离；文件同步也不等于已验证所有断电场景。

## 接受任务之后

委派快照的机器正本是 `schemas/expert_execution.json`，引用已有装配及组件声明契约。当前流的授权证据优先从已有读视图查询；跨会话证据采用只读扫描来源流水，缺失或损坏都拒绝使用。跨会话大流水的查询成本尚未压测，不宣称已经完成索引优化。

接受前完成模型目录解析，不以当前运行模型的合成列表项冒充真实目录条目。缺模型、缺凭证、损坏配置或缺授权证据都拒绝，不自动换模型。主模型和压缩模型的实际配置一并进入快照；模型目录身份和供应商型号分别保留。

接受后修改或删除候选文件、修改或删除模型目录，不改变本次任务。快照无效或宿主不支持快照时明确失败，不能退回当前同名模板。原有前台、后台、取消和重启清账规则不变：一份工具结局，重启不重跑旧任务。

快照仍需要本机随货组件实现；工厂不跨部件边界传递。它不冻结凭证值、文件系统、项目规则和技能内容，也不承诺跨二进制版本可重复执行。新子流在自己的启动边界处理所选凭证的环境隔离和聊天脱敏，不扩大已运行父流的脱敏清单。

## 验证边界

生产测试经过真实预检、信任闸、启用存储、解析器、子流宿主、内核和文件工具。模型传输使用脚本；真实模型配置的规范化另有不联网检查，不等于已向供应商发送并验收。

测试覆盖授权等待期间的修改、接受后的修改和删除、读写能力对照、拒绝、重启后的可用性与不重跑，以及检查结果不得混用两个版本的竞争条件。关键断言保留反向验证。完整管理功能和人工体验仍由 #45 跟踪。
