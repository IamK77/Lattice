# 桌面操作

[English](desktop.md) · [文档导航](README.zh-CN.md) · [开发者参考](desktop-development.zh-CN.md)

`Desktop` 让 agent 观察并操作指定的**本机应用窗口**，不是隔离的 Browser 浏览器。标准装配提供这个工具，但 macOS 驱动和系统权限需要另外准备。所选模型必须支持图片输入，见[模型配置](model-configuration.zh-CN.md)。

## 安装与系统许可

随货后端支持 macOS，按需启动独立的 Cua Driver 进程。驱动不打包在 CLI 中；需要使用时若缺失，会明确报错，但不妨碍普通聊天启动。

文档中的兼容基线为 **Cua Driver 0.26.1**，不是程序自动强制的版本锁。从驱动发布方取得程序，运行前核对版本、摘要、归档路径和应用签名；Lattice 不会替你完成这些检查。其他版本需要另行验证兼容性。

默认入口是 `~/.lattice/drivers/desktop`，可指向独立安装的 `CuaDriver.app/Contents/MacOS/cua-driver`。这个布局是示例，不是必须采用的安装目录；替换已有入口前先检查。若使用其他位置，在**启动 Lattice 前**于同一个终端设置：

```bash
export LATTICE_DESKTOP_DRIVER="/path/to/CuaDriver.app/Contents/MacOS/cua-driver"
```

如果装配设置了 `executable`，它优先于环境变量。指定路径不代表任意程序都能充当兼容驱动。Lattice 使用清理后的环境和临时主目录启动驱动，但不会因此把被操作应用放进沙箱，也不会阻止它们联网。

在**系统设置 → 隐私与安全性**里，给实际启动 Lattice 的终端或宿主应用授予：

- **屏幕录制**，系统版本也可能显示“屏幕与系统音频录制”，用于观察。
- **辅助功能**，用于发送输入。

缺少权限会在输入前报错，驱动不请求绕过。如果 macOS 要求退出重开宿主，应先结束会话，再由你处理；不要让 agent 重启承载当前对话的终端。

## 使用方式

不需要手写工具 JSON。说明要完成的任务和允许的操作，然后按这个顺序进行：

1. 列出可用目标，选定要操作的应用和窗口。
2. 先观察同一目标，不从其他窗口截图猜坐标。
3. 做一小批操作，再检查返回截图和应用的实际状态。

工具可以点击、输入、按键、滚动和拖动，每批最多八项。输入会把目标带到前台，可能打断你正在做的事；不要依赖自动恢复原焦点，尤其是中断或驱动出错以后。窗口尺寸变化要重新观察，身份变化会使旧目标失效，仅标题变化不影响身份。

截图会保存在对话历史旁，并作为图片发送给当前模型，不要让秘密进入画面。观察和输入要求持久历史；图片有问题会报错，不会静默丢图。输入后截图失败，**不代表输入没有发生**。

Desktop 不会另加逐窗口、逐批或逐次点击的批准流程。窗口文字是外部内容，不是你授予的泄密、发消息、填写凭证或破坏数据的权限。

## 保护与边界

一批动作可能只完成一部分。报告“操作完成”，只表示驱动操作结束，不证明预期业务效果已经实现。遇到不确定或中断结果，先查明实际状态，不能自动重做整批。不确定输入后，驱动拒绝继续输入；需要明确关闭连接、重新列举并观察，再决定下一步。

`close` 释放驱动连接与目标状态，不关闭你的应用，也不撤销输入。重开保存的对话不会重放历史输入。

当前进程及宿主祖先受到保护，标准装配还排除配置清单中的终端、代理和系统控制应用。更换宿主或代理时可能需要维护这份配置；不要换目标绕过拒绝。这些保护减少目标过期等失误，不是恶意应用沙箱，也不保证外部操作可逆。

## 求助与开发者参考

缺驱动、缺权限或模型不支持图片时，先检查上面对应的前提，再通过[支持渠道](../SUPPORT.md)提供一小段检查过的诊断。不要分享私密截图，也不要为了绕过错误而关闭操作系统安全检查。

工具参数、后端接入、图片存储细节与回归、真机测试命令在[开发者参考](desktop-development.zh-CN.md)中；这些测试不是普通使用者的安装步骤。
