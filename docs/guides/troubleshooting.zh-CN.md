# 故障排查

[文档导航](../README.zh-CN.md) · [English](troubleshooting.md) · [安装与升级](installation.zh-CN.md) · [支持渠道](../../SUPPORT.md)

按下面的现象找到对应步骤。通常先检查程序版本、配置路径和具体错误即可。请保留 `~/.lattice` 和已有模型配置，其中有账号设置与对话记录。求助时提供相关错误片段，并去掉密钥和项目中的敏感内容。

## 执行了旧程序，或平台不匹配

先用 `command -v lattice` 和 `lattice --version` 确认实际运行的是哪一份程序，再检查命令链接是否指向预期版本。开发构建会在版本信息中标明身份。

程序无法启动时，记录系统版本、处理器架构和完整错误，对照[实测平台表](installation.zh-CN.md)。缺少动态库或符号时，查看包内的 `SYSTEM-DEPENDENCIES.txt`。旧系统可能需要换用表中已测试的环境，或从源码构建。下载包被系统拦截时，先按安装页验证来源，再根据具体报错处理。

Linux 源码构建需要 OpenSSL 开发头文件与 `pkg-config`；请安装开发包。浏览器、桌面驱动、语言服务和 Ink 客户端的准备步骤见[第一次对话](getting-started.zh-CN.md#可选工具)。

## 没有可用模型，或连到了意外的提供方

按[模型配置](model-configuration.zh-CN.md)检查服务地址、接口格式、模型名和密钥。若提示配置文件无法读取，先备份该文件，再按错误提示修复。Lattice 会保留原文件，避免覆盖已有账号配置。

### 保存的配置找不到，或没有被采用

先检查配置文件路径。`LATTICE_MODELS` 指定模型配置文件；设为空值时，会停用默认文件。编辑配置时保留已有模型。

接着检查是否设置了 `LATTICE_ADAPTER`、`LATTICE_MODEL`、`LATTICE_BASE_URL`、`LATTICE_API_KEY_ENV`。其中任意一个存在，启动就会改用整套环境变量配置。想使用保存的模型时，从本次启动环境中移除这四项；想使用环境变量时，把这套配置填完整。检查变量名称即可，密钥值留在本机。

使用保存的配置时，Lattice 优先选择上次选定且凭证可用的模型，再尝试配置文件中第一个有凭证的模型。原模型缺少凭证时会提示回退；已删除的模型会直接跳过。用 `/model` 查看实际选中的模型，再继续发送工作内容。

### 提供方拒绝请求

核对服务根地址、准确模型名、容量、接口格式和相关设置。错误明确指出不支持思考参数时，可以省略这个参数。先按[第一次对话](getting-started.zh-CN.md)设置 `LATTICE_BIN`，再运行：

```bash
LATTICE_THINKING= "$LATTICE_BIN"
```

这里的空值表示省略思考参数。其他两种用法分别是：未设置变量时采用保存的偏好，缺少偏好则用 `high`；设为 `off` 时明确请求关闭思考。

### 回答像预写脚本，而不是真实模型

检查并移除 `LATTICE_SCRIPTED`。只要这个变量存在，就会启用测试模式，设为 `0` 也一样。测试模式仍会加载配置中的运行时扩展，工具仍可操作本机文件。

## 找不到对话，或历史似乎损坏

先回到创建对话时的项目目录，按[第一次对话](getting-started.zh-CN.md#4-继续之前的对话)设置程序路径，运行 `"$LATTICE_BIN" -c` 继续最近的对话。

要打开其他对话，可以在文件管理器中打开 `~/.lattice/ledgers/`，按日期找到对应的 `.ledger` 文件夹并复制它的名称。把下面的示例名称换成刚复制的名称，再从原项目目录运行：

```bash
"$LATTICE_BIN" --resume "conversation-name.ledger"
```

查找范围是当前项目；尚未记录项目的旧对话也会被查找。名称未找到时，错误信息会列出当前项目最近的几个对话名。

新的终端对话保存在 `~/.lattice/ledgers/`；旧的 `tui/`、`chat/` 位置也会被查找；后台服务使用 `~/.lattice/streams/`。备份时一并保留记录引用的文档和附件。查找路径时检查 `HOME` 及各项独立路径设置；`LATTICE_HOME` 不会统一改变这些存储位置。

### 进阶：不改动历史，只做检查

历史报错时，先备份完整记录和引用的文件，见[升级与回退](installation.zh-CN.md#升级时保留旧程序)。然后按需要选择只读检查：

- `lattice --recover PATH --offset BYTES --bytes COUNT`：读取指定范围的原文，无需加载模型凭证。
- `lattice --verify-ledger DIRECTORY`：完整校验分卷保存的对话记录。

检查结果先留在本机，分享时取出相关片段并去掉秘密。正常恢复对话会处理未写完的记录末尾，并记录上次中断的调用；需要保持文件原样检查时，使用上面的只读命令。

`compact`、`tidy`、`--migrate-ledger` 用于整理或迁移数据，会涉及写入、移动或删除。准备迁移时，先停止使用源文件的会话，再按[安装与回退](installation.zh-CN.md)准备备份。迁移会保留源文件，存放在目录外的附件也需要一并保管。

## 工具或扩展表现异常

工具能访问当前项目目录以外的文件。操作取消或中断后，先检查文件、进程或外部服务中的实际结果，再决定是否重试。

按工具类型检查所需程序：

- **代码导航：** 按提示安装对应语言的语言服务。
- **浏览器：** 检查是否已安装 Chrome/Chromium。
- **桌面操作：** 按[桌面配置](desktop.zh-CN.md)检查外部驱动和 macOS 权限。
- **Ink 客户端：** 按[客户端说明](../../clients/ink/README.zh-CN.md)检查后台服务是否运行，以及两端连接路径是否一致。

自行定制过运行时的话，再检查完整装配与后来安装的扩展。`assembly.json` 通常记录的是后加的扩展，完整配置另见[装配配置](../development/assembly-configuration.zh-CN.md)。导出的配置可能含有密钥和提示词，分享前检查内容。

## 适合提供给维护者的信息

请提供程序版本、系统和架构、安装方式、复现步骤、预期与实际结果，以及去掉密钥的错误片段。下载验证失败时，附上版本或预演运行编号，以及失败的步骤。敏感安全问题使用[私密报告渠道](../../SECURITY.md)。
