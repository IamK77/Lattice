# 开始与 Lattice 的第一次对话

[首页](../../README.zh-CN.md) · [文档导航](../README.zh-CN.md) · [English](getting-started.md)

让 Lattice 先帮你读懂一个项目，再一起完成一项小修改。下面从启动程序开始，带你连接模型、提出问题，并在下次回来时继续对话。

准备一个模型服务账号和 API 密钥，调用费用由模型服务收取。Lattice 能读取文件、修改代码和运行命令，也能访问项目目录以外的文件。第一次使用可以选一个练习项目，先保存好已有工作。

## 1. 构建 Lattice

**已有程序？** 刚按首页构建完成的话，在 Lattice 源码目录执行 `export LATTICE_BIN="$PWD/target/release/lattice"`。已经安装到其他位置的话，用 `export LATTICE_BIN="/path/to/lattice"` 设置实际的程序完整路径。然后直接进入[第 2 步](#2-连接模型)。

第一次构建时，按下面操作。源码构建适用于 macOS 和 Linux。需要先装好 Rust/Cargo 和 C 工具链；Linux 还需要 OpenSSL 开发库与 `pkg-config`（Debian/Ubuntu 上的包名是 `libssl-dev` 和 `pkg-config`）。其他安装方式见[安装与升级](installation.zh-CN.md)。

在终端中执行下面的命令。它们使用 **Bash**；如果你用的是其他 shell，先输入 `bash`：

```bash
git clone https://github.com/IamK77/Lattice.git
cd Lattice
cargo build --locked --release --bin lattice
export LATTICE_BIN="$PWD/target/release/lattice"
"$LATTICE_BIN" --version
```

看到版本号后，继续使用这个终端。这里用 `LATTICE_BIN` 记住程序的位置，方便切换到自己的项目。新开终端时重新设置这个变量即可。已经安装过 Lattice 的话，可以直接用已有的程序。

## 2. 连接模型

把下面的路径换成你的项目目录，然后启动：

```bash
cd /path/to/your/project
"$LATTICE_BIN"
```

### 分步引导

首次连接模型时，Lattice 会打开配置引导。在首页选择 **Language / 语言** 可以切换为中文。配置可用时会直接进入对话。

1. **连接服务。** 选择你的模型服务，核对服务地址，填写 API 密钥。已经把密钥放进环境变量的话，填写变量名即可。
2. **选择模型。** 从服务提供的列表中选择，也可以直接输入模型名称。获取列表失败时，仍可手动填写。
3. **检查并保存。** 确认模型和服务地址。页面询问容量时，按服务说明填写；[模型配置](model-configuration.zh-CN.md#能力与容量)解释了这些数值。其他选项在**更多设置与详情**中。
4. **开始对话。** 你可以先做一次连接测试，看看服务能否回答。测试会发送一个简短问题，按服务的计费规则收费；也可以直接跳过。

按 Esc 返回上一步，在首页按 Esc 退出。更多操作说明见[返回与保存](model-configuration.zh-CN.md#语言返回与保存)。

**保管密钥：** 建议填写保存密钥的环境变量名，减少配置文件中的密钥副本。工具能够读取配置文件和环境变量；读到的密钥会进入对话记录，并可能随对话发送给模型服务。提交代码或分享记录前，请检查其中的密钥。

### 手动配置（可选）

喜欢直接编辑配置文件的话，见[模型配置](model-configuration.zh-CN.md#手动配置)。

## 3. 提出第一个问题

在对话输入框输入 `/model`，按回车查看当前模型。按 Esc 关闭模型面板，再输入下面的问题并按回车发送：

> 帮我了解这个项目：它是做什么的，主要代码在哪里，测试怎么运行？这一步先读文件，把你的发现告诉我。

读完回答，再挑一个小任务，例如补一条测试或解释一处报错。让 Lattice 完成后展示修改和测试结果，方便你检查。

暂时结束时，输入 `/exit` 并按回车。下次可以继续这段对话。

## 4. 继续之前的对话

新开终端后，先指定程序位置，再回到项目目录。把下面两处示例路径换成你的路径；源码构建的程序在第 1 步仓库的 `target/release/lattice` 中：

```bash
export LATTICE_BIN="/path/to/Lattice/target/release/lattice"
cd /path/to/your/project
"$LATTICE_BIN" -c
```

Lattice 会接着最近的对话继续。模型密钥也需要像上次一样配置好。关于查找其他对话，见[故障排查](troubleshooting.zh-CN.md)。

如果上次在修改文件或运行命令时中断，先让 Lattice 检查进展，再决定接着做什么。已经写入的文件和已经发出的请求会保留，恢复对话时也会保留这些操作的记录。

## 5. 加入项目约定

想让 Lattice 按项目的习惯做事，可以在项目的 `AGENTS.md` 或 `CLAUDE.md` 中写下约定。已有文件时，在原内容上补充。例如：

```text
修改前，先说明你准备怎么做。
每次集中完成一个任务。
修改后运行相关测试，并告诉我结果。
需要添加依赖时，先和我讨论。
```

Lattice 启动时会从当前目录向上查找这些文件，读取最近一个包含规则文件的目录。修改约定后，启动新会话即可使用。项目约定用来指导模型如何工作；文件访问权限仍由系统和工具的配置决定。

## 可选工具

完成第一次对话后，可以按任务需要准备这些工具：

- **浏览器：** 安装 Chrome/Chromium。`LATTICE_BROWSER` 可以指定浏览器程序的位置。
- **代码导航：** 安装所用语言的语言服务，让 Lattice 查找定义和引用。缺少时，工具会提示需要什么。
- **桌面操作：** 在 macOS 上按[桌面配置](desktop.zh-CN.md)安装驱动并开启系统权限。
- **其他客户端：** 试试 [JavaScript/Ink](../../clients/ink/README.zh-CN.md)。

## 数据与权限

了解下面几项，方便你选择适合交给 Lattice 的工作：

- **对话资料。** 对话、工具操作和附件保存在本机，并可能发送给你选择的模型服务。浏览器和桌面截图也会保存并发送给模型。
- **停止任务。** 取消后，已有修改和对外发送仍然保留。工具启动后独立运行的程序可能继续执行，重试前先检查文件和运行中的程序。
- **安装扩展。** 选择可信来源。允许安装某个扩展，与确认它的一次具体操作，是两件事。同一网址或路径的安装授权会继续有效，即使内容后来改变。永久授权默认保存在 `~/.lattice/trust.json`，撤销时需手动编辑这份记录，字段见[授权文件格式](../../schemas/trust_grants.json)。

## 遇到问题时

先按现象查[故障排查](troubleshooting.zh-CN.md)，例如构建失败、模型连不上或找不到之前的对话。求助时提供操作步骤和去掉密钥的错误信息，保留本机原有配置和记录。[支持说明（英文）](../../SUPPORT.md)列出了报告问题的方法和私密报告安全问题的渠道。
