# Lattice 架构总览

Lattice 是一个由松耦合部件组装起来的 agent runtime。模型、工具、对话主循环和界面都不属于内核；它们可以被替换，也可以作为独立进程运行。进程外部件不绑定 Rust，Python 等语言使用同一份逐行 JSON 契约。

## 两条地基

1. **部件边界只传纯数据。** 跨边界的消息必须能完整序列化，没有回调或内存对象引用。分散运行改变的是运输方式，不是事件的含义；当前跨进程桥用子进程的标准输入、标准输出管道，并非 HTTP。
2. **事件流水是持久层，也是审计正本。** 先记账，再投递。每条事件携带因果列表，跨流则用 `origin` 弱引用。重放只看历史，不重新执行历史操作。

## 先区分三份东西

- **部件自述**说“我是谁、提供哪些口和工具、会碰到哪些作用面”，还可以提供提示片段与默认接线建议。它不是运行实例，也不是安装授权。
- **装配说明书**说“启动哪些实例、各给什么配置、哪一个输出口接哪一个输入口”。同一部件可以有多个实例。运行时只执行这张接线图，不替用户猜线路。
- **实现**才是实际干活的程序。进程内实现由宿主工厂构造；进程外实现由宿主启动程序，经过桥接协议接收事件、发出草稿与完成回执。

产品默认基线由代码生成。用户可用 `LATTICE_ASSEMBLY` 指定完整基线，替换实例、配置和接线；`lattice assembly` 导出所选基线供检查和修改。选定文件读坏或体检失败就拒绝启动，不退回另一套线路。

安装记录是另一层：`~/.lattice/assembly.json` 只在基线上增补部件、实例和接线。它不覆盖基础实例，不删除基础接线。安装工具能管理增补部分，不能借卸载拆掉基础关卡。完整文件与增补文件的边界见《装配配置》。

## 内核只管四件事

| 职责 | 做什么 | 不做什么 |
|---|---|---|
| 保管流水 | 编号、盖时间戳、校验信封与信纸、写盘、回放和订阅 | 不解释业务内容 |
| 执行装配 | 启动前检查部件、口、类型和所需口型，照说明书构造实例 | 不发明接线 |
| 搬运事件 | 校验发射口和因果见证，记账后按接线投递；工具按声明的主人定向送达 | 不决定工具该怎么执行 |
| 托管生命周期 | 启动、停止、处理超时与崩溃，给未知结局记打断 | 不理解专家、任务或会话 |

宿主可以停止整个流：内核停止继续投递，取消在途工作，保留迟到的结果并清结悬链。这是通用生命周期操作，不是专家专用入口。进程内代码若拒绝配合，不能保证它已经停止；进程隔离也不等于沙箱。

## 一轮对话怎样流动

随货的最小主循环采用“问模型、执行它提出的工具调用、收齐结果再问”的方式：

```text
用户输入 → 技能展开 → 主循环
                         ↓
                       上下文闸 → 模型适配件
                         ↑            ↓
                    下一次提问 ← 主循环
                                      ↓
                                  信任闸 → 工具
                                      ↑      ↓
                                      主循环收结果
```

这段循环本身也是部件。内核不要求每个系统都必须围绕模型运行，但当前随货循环不是任意工作流编辑器。

上下文闸选择交给模型的材料；压缩只改变视图，不删改历史。适配件负责供应商方言与流式传输；模型输出和工具结果完整后才入账，小片段仅作实时通知。同一个工具请求经过关卡转发会有多个事件编号，但仍是同一条调用链，不是执行了多次。

## 流、支线与专家

核心顶层容器叫“流”：一份独立编号的事件序列。“会话”是前端的称呼，“任务”属于未来的调度层。

- **支线对话**供人来回切换、继续交谈，各自保有执行和界面状态。它不与父线混用材料。
- **专家委托**由 `ask` 发起。专家使用独立装配模板和空白上下文，结束后回报结果，留下可读的流水文件。主 agent 可以用 `CancelExpert` 按编号取消自己委托的工作；收到取消请求不等于执行已停止，最终回报另行送回，已发生的操作不自动回滚。
- **完整调度层尚未建成**。专家委托没有任务图、优先级或仲裁，不能把它当作调度层。调度层接入时不得修改现有核心契约，是已经确定的验收约束，不是建议。

## 边界与故障

随货信任闸已经实现，安装授权与接线不需要内核认识工具名。作用面由工具自述，当前防误操作而非防恶意；作用范围没有沙箱执法。严格信任闸可以另行实现，WASM 沙箱仍在挂账。

写盘失败会停止当前内核运行，不能让未记账的指令继续执行。部件崩溃则记控制事件、结清其持有的调用，其余部件继续运行。重启发现无结局的调用时记 `interrupted`：它说明“不知道干到哪里”，不是伪造一次失败，更不是自动重试。

完整信封、部件自述、装配和跨进程协议的正本在 `schemas/` 与 `docs/contracts/`；各子系统为什么采用这些形状，见《架构决策》。
