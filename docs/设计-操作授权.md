# 操作授权与界面临时权限

本文记录 #38 已定的职责与边界。当前提交提供底层部件和测试；默认装配、宿主完整生命周期与界面入口属于后续接入，不能把本文当成已可使用的界面说明。

## 两种不同寿命的许可

**流内操作授权**回答“在这条流里，以后遇到同类操作是否还要问”。授权与撤销都记入流水，重开同一条流仍有效；另一条流不继承。撤销不回滚已经执行的操作，也不删除永久信任记录。

**界面临时权限**回答“这个实际发来工作输入的界面，现在是否允许免去询问”。一个界面实例只绑定一条流，一条流可以接多个界面；界面不等于终端窗口，也可以是机器人入口。开启、关闭和退出都有审计记录，但恢复历史不会恢复这项权限。永久信任和流内授权不会因为关闭界面开关而被删除。

旁观某条流并不参与授权。一个模型请求真正消费了多个界面的输入时，只要其中一个来源仍有临时权限，就可以免去询问；尚未消费的插话不能追溯批准已经发出的工具请求。最终答复结束旧工作，下一项工作不借用上一次说话人的权限。后台完成、定时器和监控沿创建它的调用追溯来源，而不是取最近说过话的人。跨流弱引用只用于导航，不用于继承授权。

## 职责分开，内核不识别权限

- `effects-policy` 仍只按装配实例配置检查工具声明的读写、联网与执行作用面，不是按用户授权，也不是沙箱。
- `operation-policy` 匹配操作规则，提出确认，保存与撤销流内授权，并转交已有服务的授权答复。
- `interface-permissions` 保存当前界面的归属与开关状态，恢复时清空活权限。
- `trust-policy` 保留引入新代码、指令的确认与永久信任，同时接受适用的流内授权和界面临时权限。临时或流内批准不能写入永久信任。
- Browser、专家删除等服务保留自己的参数、版本、快照与执行校验；许可只替代适用的询问。
- 宿主负责界面身份和连接寿命；界面负责展示与收集决定。部件之间只读写可序列化事件，不共享一张可变的内存授权表。

内核仍只负责记账、投递、见证和调用结局，不增加“权限模式”的特殊分支。

## 命令匹配

命令规则匹配的是参数数组前缀，不是字符串子串。例如 `["git", "push", "origin"]` 可以覆盖同一远端的后续推送，但不覆盖 `upstream`，也不把 `push-other` 当作 `push`。多个规则同时命中时，禁止高于询问，询问高于允许；流内授权不盖过显式禁止或询问规则。界面临时权限可以跳过询问，但不能盖过禁止。

对于能够可靠解析的组合命令，逐条审查，全部许可后才将**原脚本完整交给执行方**。不会先执行已获准的一半。动态展开、重定向、循环等不支持的语法不作猜测，而是退回对完整 `bash -c` 请求的审查。

可持久化的建议由服务端生成，答复不能夹带一条更宽的新规则。裸解释器、包装器和没有明确远端的 `git push` 不自动获得宽前缀；这类请求只能保存原样参数授权。配置为必须询问的规则不提供一个实际上永远不会生效的流内允许选项。

**前缀不是执行隔离。** 它不约束后续参数、工作目录、远端名字对应的实际地址、PATH 指向的程序或脚本内容。整体参数授权也不是文件内容指纹。工具作用面的声明仍不是针对恶意部件的强安全边界。

解析器借鉴固定版本 Codex 的保守 Bash 解析方式；归属见根目录 `NOTICE` 和源文件说明。这里只复用了参数解析思路与对应实现，不引入 Codex 的沙箱策略或未命中规则的自动放行推断。

## 数据与恢复

模型请求通过 `workInputs` 指向本次工作实际消费的输入，工具续轮继续携带它，最终答复或等待状态结束它。取权限时不把整段历史材料当成来源，也不把授权答复的发送者算成原工作来源。没有来源标记的旧模型请求不猜测身份。回查错误不能当成“没有来源”。

界面服务发布 `interface.permission.state`，操作服务发布 `operation.authorization.state`。使用方按配置中的实例名读取权威快照。可以通过 `interfacePermissions` 和 `operationPolicy` 指定非默认实例名；改名必须同步配置相关使用方。界面控制命令只接受配置中的控制方，已经关闭的实例不能在当前运行寿命内重新启用。

宿主必须为每次新绑定分配新身份，不能让远程客户端自行冒认旧身份。默认身份生成器包含流标识、当前流水位置和进程内序号；断线、退出与重开不能把旧后台工作的身份重新赋给新界面。完整的宿主绑定和断开处理仍属于接入层的责任。

操作确认使用 `scope=once` 或 `scope=flow`。显式指定了错误类型或未知范围的答复不消费问题，也不降级成永久信任。为了兼容既有调用方，没有范围字段的旧布尔答复继续沿用原有服务语义；对 trust 而言那是原来的永久信任选择，界面不能把它标成“仅本次”。流内引入授权还保存当时声明的作用面，声明变化需要重新确认。

恢复只重建流内授权，不重放旧确认或执行操作。停止按同一调用的转发链判断；用户停止后才从上游送达的旧请求也必须结束为中断，新工作则不受之前的停止影响。撤销和停止都不是回滚。
