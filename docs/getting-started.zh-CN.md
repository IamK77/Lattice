# 开始与 Lattice 的第一次对话

[首页](../README.zh-CN.md) · [English](getting-started.md)

这份指南从源码构建开始，带你在自己的项目里进行真实对话。模型账号和 API 密钥由你提供，使用模型可能产生提供方收取的费用。二进制不附送账号或可直接使用的模型配置。

## 1. 构建 Lattice

发布状态、实测平台、产物验证、安装和回退，先看[安装与升级](installation.zh-CN.md)。首个正式版本发布前，下面的源码路径仍然可用。

使用 macOS 或 Linux，准备 Rust/Cargo 和 C 编译工具链。Linux 还需要 OpenSSL 开发库与 `pkg-config`；Debian/Ubuntu 对应的软件包是 `libssl-dev` 和 `pkg-config`。这份指南不提供 Windows 上的完整使用路径。

下面的命令使用 **Bash**。如果正在使用其他 shell，先进入 `bash`。配置过程中保持同一个终端，以保留导出的变量。

```bash
git clone https://github.com/IamK77/Lattice.git
cd Lattice
cargo build --locked --release --bin lattice
export LATTICE_BIN="$PWD/target/release/lattice"
"$LATTICE_BIN" --version
```

`LATTICE_BIN` 只是本指南使用的便利变量，不是 Lattice 配置项。它保存程序的绝对路径，让你切换到自己的项目目录后仍能启动程序。打开新终端后需要重新设置，或直接使用程序的完整路径。

## 2. 连接模型

### 分步引导

进入你的项目目录，在交互终端运行 `"$LATTICE_BIN"`。如果模型配置不完整，Lattice 会在**创建对话、打开主界面之前**进入分页引导：

1. **连接服务。** 选择提供方（OpenAI、Anthropic、DeepSeek）、自定义服务，或修复已有条目。提供方自动带出推荐接口格式和地址，在填写密钥前即可查看和修改；自定义服务则需要填写格式和地址。输入隐藏显示的本机密钥，或填写已有且非空的环境变量名。
2. **选择模型。** 明确选择获取服务的模型列表，输入文字筛选；也可以直接手填准确名称。已获取的名称会作为输入建议，支持 Tab 补全，不额外联网。获取失败或列表为空不挡住手填。获取列表只是 GET，不生成回答，也不能证明接口和工具兼容。
3. **检查一次。** 紧凑总览显示模型、易读的接口名称（例如 OpenAI Chat Completions）、地址、建议的本地名称、默认偏好保存动作和主要能力。**更多设置与详情**中保留完整配置、保存位置、能力来源，以及名称、默认项和语言设置。资料完整时直接进入总览，只追问缺失或无效的容量。可以进入某项修改后返回这里。选择不修改默认偏好，不会取消以前已选定的默认模型。
4. **保存并开始。** 跳过可选连接测试进入主界面，或明确发送一次简短、可能收费的请求。测试失败后可主动重试、修改配置、跳过或退出，不会自动重试。

**页面与终端：** 当前任务原地替换上一页，重试只更新错误，不追加问答记录；长说明单独分页。引导使用临时屏幕，取消、普通错误及交给主界面时均恢复启动前的终端画面。标准输入、输出和错误流都需要连接交互终端，窗口至少 40 列、14 行。切换问题和详情页时会重新计算布局；正在等待输入时缩放窗口，不会立即重排整页。

**能力编辑：** 空格勾选，回车确认，预选已有值。图片输入与服务端图片生成分开，服务端搜索和图片生成仅在 Responses 下提供；未知能力不勾选。思考档位复选框声明支持的范围，不改变当前强度：常见名称由弱到强排列，自定义名称保留原有顺序。高级设置保留自定义档位名称与顺序、用量字段映射。

**输入辅助：** 填错时留在当前输入框纠正。过长名称仍可在已获取的模型列表中搜索选择；输入框下不展开会折行的补全候选，更不会把截短后的名称当作真实型号提交。容量可填精确整数，也支持不区分大小写的十进制缩写：`1M = 1000k = 1000000`，`1.5M = 1500000`；提交后回显展开的数值。这不是二进制单位，服务若明确给出 `1048576`，就填写该精确值。不接受小数个 token 或溢出，不会四舍五入；输出上限必须给输入留出空间。

**语言：** 配置引导与密钥修复支持简体中文和英文，不改变主 TUI 的语言。初始语言依次参考 `LC_ALL`、`LC_MESSAGES`、`LANG`；中文环境使用简体中文，其他环境使用英文。在首页或新模型总览的**更多设置与详情**中选择 **Language / 语言** 即可切换，不丢草稿；密钥修复总览直接提供语言选项。明确选择会以 `setupLanguage`（`en` 或 `zh-CN`）保存在偏好中，优先于环境判断；自动判断不写文件。保存失败时本次仍采用选定语言，并明确提示未能记住。服务端诊断标明为原文。

输入上限不一定等于总上下文容量。对 Anthropic 返回的输入上限，引导会明确标为**保守的总预算建议**，不会加上输出长度冒充服务报告的总窗口；需要确认或修改。返回修改时，同一型号已经手动改过的能力不会被新获取的资料覆盖。提供商格式预设有文档依据，但不是每个型号、每项能力都通过了实测的承诺。

Esc 返回上一步（在首页则退出），等待输入时 Ctrl-C 退出。网络请求进行中，取消按键会在这次有界请求结束后处理，不会因此重发请求。已经提交的字段保留在草稿中，取消前尚未提交的输入不算完成。保存模型前取消，不创建模型条目或对话；明确保存的语言偏好及此前已保存的配置仍保留。返回首页保留新建和密钥修复草稿。换地址、格式或账号使依赖的列表与能力失效，换型号重新匹配能力；换地址绝不自动携带旧密钥。已有可用配置时跳过引导，后台或非交互命令不弹出问答。原本要继续的对话不会因此换成另一条。

本机密钥存放在 **agent 能读到的文件**中；文件工具读取后，可能进入持久流水和模型上下文。Unix 上写入器在写入凭据之前就以仅所有者可读写的权限创建临时文件，但这不意味着 agent 读不到密钥。仍可选择环境变量引用，引导不修改 shell 启动文件。其他平台没有受保护写入能力时，不会把本机密钥保存伪称为安全选项。

模型列表获取和连接测试是前端操作，不是聊天消息。每次明确请求的操作，在模型目录文件旁的 `setup-tests/` 下单独记录请求意图和结局，不记录密钥、请求正文或提供方回复正文。列表获取支持有界的 Anthropic 分页，限制响应大小、条目数和总时长；不跟随重定向，不自动重试。只有请求、没有完成记录表示结果未知，不会重放。短文本测试成功不等于工具、思考历史或全部提供方能力都已验证。DeepSeek 模板所依据的官方参考列在 `src/bin/lattice/setup/deepseek.json`，真实账号验收另做。

损坏的目录不会被重置。按提示修好文件后可以重新检查。模型已保存但默认偏好保存失败时，引导会明确说明，并允许本次继续使用。以后启动时，外部环境里的明确模型设置仍优先于保存的偏好。

### 手动配置（可选）

默认模型目录文件是 `~/.lattice/models.json`。必要时先创建父目录：

```bash
mkdir -p "$HOME/.lattice"
```

用编辑器创建或编辑 `models.json`。**如果文件已存在，请保留已有条目。** 也可以用 `LATTICE_MODELS` 指定另一份目录文件的路径。

下面是配置形状示例，不是可以直接使用的模型账号。请按提供方的文档替换端点、型号和模型上限；`.invalid` 端点特意不能作为真实服务使用。

```json
{
  "models": {
    "my-model": {
      "adapter": "openai",
      "model": "your-model-id",
      "baseUrl": "https://api.example.invalid/v1",
      "apiKeyEnv": "LATTICE_MODEL_KEY",
      "profile": {
        "contextWindow": 32768,
        "maxOutputTokens": 4096
      }
    }
  }
}
```

按端点使用的协议选择适配件：

| 适配件 | 端点协议 |
| --- | --- |
| `openai` | Chat Completions |
| `responses` | Responses |
| `anthropic` | Anthropic Messages |

这是协议选择，不代表支持每家提供方的所有扩展。端点根地址、型号、上限和其他必要的型号设置应以提供方文档为准。配置参考：[模型目录](../schemas/model_catalog.json)与[型号档案](../schemas/model_profile.json)。

通过已有的凭证管理方式提供密钥，或者交互输入，避免把密钥值直接写入 shell 历史：

```bash
printf 'API key: '
read -r -s LATTICE_MODEL_KEY
printf '\n'
export LATTICE_MODEL_KEY
```

这只是避免将密钥写进命令文本，**不代表 agent 无法读取环境变量或工具输出**。不要提交真实密钥；优先使用 `apiKeyEnv` 引用环境变量名，而不是把密钥值存进目录文件。

## 3. 在自己的项目里启动

切换到一个你愿意授予 agent 文件访问权限的项目目录。运行前替换示例路径：

```bash
cd /path/to/your/project
"$LATTICE_BIN"
```

用 `/model` 查看当前模型，并在已配置的条目之间切换。保存的偏好与已有启动环境变量可能影响初始选择。

第一次可以先要求理解，而不是修改：

> 解释这个仓库的结构，找出主要入口和相关测试。先不要编辑文件，也不要运行项目命令。

接着选择一个小范围、便于检查的任务。自己检查差异和测试结果。文字指令可以指导 agent，但不是操作系统层面的权限隔离。

## 4. 继续之前的对话

在模型凭证仍可用的终端中运行：

```bash
"$LATTICE_BIN" -c
```

这会继续当前项目目录可见的最近一段对话。旧记录若没有项目标识，仍对所有项目可见；具名恢复也遵循同一可见范围。它不会重新执行历史工具操作。被中断的操作可能已经部分生效；重试前检查记录、实际文件或进程。取消不等于回滚。

其他运行入口和环境变量见 `"$LATTICE_BIN" --help`。记录可能包含敏感内容，分享排障材料前先检查。

## 5. 加入项目约定

在项目的 `AGENTS.md` 或 `CLAUDE.md` 中记录约定。已有文件应编辑，不要直接覆盖。例如：

```text
Explain the intended change before editing.
Keep changes focused on the task.
Run the affected tests and report their results.
Do not add dependencies without discussing the trade-off.
```

也可以用中文写同样的要求。Lattice 从工作目录向上查找最近一个含有认可规则文件的目录，在启动时读取，而不是持续刷新。修改规则后启动新会话。规则用于指导行为，不提供沙箱，也不保证模型总能遵守。

继续扩展时可以查看[部件示例](../examples/)。外部部件不限于 Rust。[自造工具演示](tool-building-walkthrough.zh-CN.md)和[装配指南](assembly-configuration.zh-CN.md)目前使用中文。完整装配配置与安装增补是不同文件，不能相互替代。

## 可选工具

- **浏览器：** 需要 Chrome/Chromium，可以通过 `LATTICE_BROWSER` 指定程序。
- **代码导航：** 需要对应语言的本机语言服务。缺少服务时明确报错，不自动安装。
- **桌面：** 随附适配件面向 macOS，需要外部驱动和系统权限，见[桌面配置](desktop.zh-CN.md)。
- **其他前端：** [JavaScript/Ink 客户端](../clients/ink/README.md)通过 Unix socket 连接后台服务；服务启动命令为 `"$LATTICE_BIN" serve`。

## 数据与权限

- **不是沙箱。** 工具能够读写文件、执行程序和联网；初始工作目录不是隔离边界。
- **本地保存不等于只在本地处理。** 对话、工具请求和结果、附件会持久保存，也可能成为发送给所选模型提供方的材料。使用浏览器和桌面工具时，截图会留存并发送给模型。
- **不能依赖自动脱敏。** 聊天脱敏不改写工具请求和结果。工具读到的秘密、会话期间取得的密钥，都可能进入持久历史和模型输入。
- **扩展需要你的信任。** 工具作用面由工具自述。信任闸防误操作，不防恶意实现；对 URL 或本地路径的授权不锁定其未来内容。目前撤销授权需要手动管理授予文件。
- **检查副作用。** 外部发送、凭证输入和系统权限需要你留意。取消不会撤销修改，也不保证所有后代进程已经停止。
- **分享前检查。** 流水、模型目录、安装增补与信任记录通常位于 `~/.lattice/`。分享或备份到其他服务前应检查敏感信息。

详细边界见[架构决策](architecture-decisions.zh-CN.md)。

## 遇到问题时

- Linux 构建找不到 OpenSSL：检查是否安装了开发头文件和 `pkg-config`，而不只是运行库。
- 没有可用模型：检查目录路径、适配件名称和导出的变量名。不要把密钥贴进问题报告。
- 提供方拒绝请求：核对端点根地址、型号、上限和受支持的设置。要完全不发送思考参数，使用 `LATTICE_THINKING= "$LATTICE_BIN"` 启动。不设置变量会使用已保存的偏好或 `high`；`off` 是明确发送关闭设置，并不是省略参数。
- 可选工具不能使用：检查上面的额外依赖；核心构建成功不代表这些依赖也已安装。

如需**不连接模型的脚本界面检查**，可以运行 `LATTICE_SCRIPTED=1 "$LATTICE_BIN"`。这是确定性测试模式，不是真实模型演示。免模型的部件示例是 `cargo run --example heartbeat`，需要在 Lattice 源码目录中运行。
