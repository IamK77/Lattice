# 开始与 Lattice 的第一次对话

[首页](../README.zh-CN.md) · [文档导航](README.zh-CN.md) · [English](getting-started.md)

这份指南帮助你在自己的项目里使用随附的终端 agent。模型账号和凭证由你提供，使用可能产生提供方收取的费用。Lattice 能够读写文件、执行程序，并把材料发送给你选择的提供方。**它不是沙箱。** 请从一个你愿意授予访问权限的项目开始。

## 1. 构建 Lattice

可用安装来源、实测平台、下载验证和回退方法见[安装与升级](installation.zh-CN.md)。从源码构建需要 macOS 或 Linux、Rust/Cargo 和 C 工具链。Linux 还需要 OpenSSL 开发库与 `pkg-config`（Debian/Ubuntu 对应 `libssl-dev` 和 `pkg-config`）。本指南不提供受支持的 Windows 使用路径。

以下命令使用 **Bash**。其他 shell 用户请先进入 `bash`，并在配置过程中保持这个终端打开：

```bash
git clone https://github.com/IamK77/Lattice.git
cd Lattice
cargo build --locked --release --bin lattice
export LATTICE_BIN="$PWD/target/release/lattice"
"$LATTICE_BIN" --version
```

`LATTICE_BIN` 是本指南的便利变量，不是产品设置；绝对路径让你切换目录后仍能启动程序。新开终端后重新设置，或使用程序完整路径。如果已经安装 Lattice，直接使用已验证的程序，不必再次构建。

## 2. 连接模型

进入自己的项目并启动 Lattice。请替换示例路径：

```bash
cd /path/to/your/project
"$LATTICE_BIN"
```

### 分步引导

需要连接模型时，引导在对话之前进行。已有配置通过本地检查就会跳过；跳过引导不代表账号或连接已经验证。请使用至少 40 列、14 行的交互终端。

1. **连接服务。** 选择提供方或自定义服务，核对地址和接口格式，填写密钥或保存密钥的环境变量名。也可以修复已有条目。
2. **选择模型。** 获取并筛选服务的模型列表，或手填准确名称。无法取得列表也不妨碍手填。
3. **检查并保存。** 核对模型、服务地址与容量，其他选项在**更多设置与详情**中。如果容量未知，请查阅提供方说明，不要猜测。引导的 **Language / 语言** 选项切换中英文，不改变主界面的语言。
4. **开始对话。** 可以跳过可选连接测试。运行测试会发送一次简短请求，**可能收费**，不会自动重试。测试成功不代表每项工具或模型能力都已验证。

Esc 返回上一步，在首页则退出；等待输入时 Ctrl-C 退出。网络请求期间，取消会在这次有界请求结束后处理。保存模型前取消，不创建模型条目或对话；已经明确保存的设置，包括语言，仍然保留。

**凭证：** 存在本机配置文件中的密钥，agent 也能读取。工具读到后，可能进入持久历史和模型输入。引用环境变量可避免把密钥值写入该文件，但不能阻止工具读取环境。不要提交真实密钥。

### 手动配置（可选）

手写模型文件、自定义端点、容量和语言的详细设置见[模型配置](model-configuration.zh-CN.md)。使用分步引导不必先读这份参考。

## 3. 提出第一个问题

在项目里打开 Lattice 后，先用 `/model` 查看当前模型，再发送敏感工作。第一次可以先要求理解，而不是修改：

> 解释这个仓库的结构，找出主要入口和相关测试。先不要编辑文件，也不要运行项目命令。

接着选择一个小范围、便于检查的任务，自己检查差异和测试结果。文字指令可以指导 agent，但不是操作系统层面的权限隔离。

## 4. 继续之前的对话

在自己的项目目录、模型凭证仍可用时运行：

```bash
"$LATTICE_BIN" -c
```

这会继续当前项目可见的最近一段对话。没有项目标识的旧记录也可能出现在列表中。恢复不会重复历史工具操作，但中断前的操作可能已经部分生效。重试前检查记录、实际文件或进程。**取消不等于回滚。**

## 5. 加入项目约定

这是可选步骤。在项目的 `AGENTS.md` 或 `CLAUDE.md` 中记录约定；已有文件应编辑，不要覆盖。例如：

```text
Explain the intended change before editing.
Keep changes focused on the task.
Run the affected tests and report their results.
Do not add dependencies without discussing the trade-off.
```

也可以用中文写同样的要求。Lattice 从工作目录向上查找最近一个含有认可规则文件的目录，在启动时读取，而不是持续刷新。修改后启动新会话。规则指导行为，不是权限限制，也不保证模型总能遵守。

## 可选工具

这些不是第一次对话的前提：

- **浏览器：** 需要 Chrome/Chromium；`LATTICE_BROWSER` 可以选择其他可执行文件。
- **代码导航：** 需要对应语言的本机语言服务；缺少时明确报错，不自动安装。
- **桌面：** 需要 macOS、外部驱动和系统权限，见[桌面配置](desktop.zh-CN.md)。
- **其他客户端：** [JavaScript/Ink](../clients/ink/README.md)（中英文混合）有自己的启动与操作说明。

## 数据与权限

- **工作目录不是边界。** 工具能够读写文件、执行程序和联网。
- **本地保存不等于只在本地处理。** 对话、工具请求与结果、附件会保存，也可能发送给所选提供方。使用浏览器和桌面工具时，截图会留存并发送给模型。
- **不能依赖自动删除秘密。** 工具读到的秘密，包括会话期间取得的密钥，都可能进入持久历史和模型输入。
- **只使用你信任的扩展。** 权限提示不是沙箱；已经授权的 URL 或路径，其内容变化后可能不再询问。永久安装信任与单次操作权限是两回事，目前撤销前者需要手动管理授予文件。
- **分享或重试前先检查。** `~/.lattice/` 下的历史与配置可能包含秘密。取消既不会撤销修改，也不保证所有后代进程已经停止。外部发送、凭证输入和系统权限都需要留意。

## 遇到问题时

构建错误、模型不可用、请求被拒、找不到对话或工具等问题，见[故障排查](troubleshooting.zh-CN.md)。不要为了重置而删除数据，也不要通过公开密钥、全部环境变量或整本对话来求助。[支持说明（英文）](../SUPPORT.md)介绍报告应包含什么，以及安全问题的私密报告渠道。

接下来按需要进入[使用、定制或开发 Lattice](README.zh-CN.md)。使用终端 agent 不需要先学习架构或部件契约。
