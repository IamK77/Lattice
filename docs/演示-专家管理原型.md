# 专家管理：首版体验

这是 #45 的功能分支原型，供体验后调整，尚不代表合入开发分支或发布。

## 打开

在本仓库构建 `cargo build --locked --bin lattice` 后，另开终端运行 `./target/debug/lattice`，输入 `/experts`。不要用 `-c` 或 `--resume` 接管正在使用的对话。也可以从 Background 面板切到 Experts 标签。

该入口使用当前项目和个人目录，操作会真实保存定义；若只想看界面，使用下方的隔离演示。

## 一条完整路径

1. 上下键选中内置专家，Enter 看详情，`c` 复制。
2. 填新的 ID，选择已有模型的目录名称，编辑说明与指令。默认项目级；Scope 可填 `personal`。
3. Tab / Shift-Tab 切字段。指令支持多行粘贴与 Enter 换行；左右键、Home / End、退格和 Delete 编辑文字。F2 提交保存，Esc 丢弃草稿。
4. 授权卡显示完整的保存前后内容。上下键选择批准或拒绝，Enter 确认。保存后状态为 `pending`。
5. `a` 请求启用，再次确认具体版本；完成后重新检查状态，显示 `ready`。
6. `d` 请求删除。删除是独立确认，不是安装授权；拒绝不会删文件。

`n` 新建，`e` 编辑，F5 刷新。长内容自动换行，PgUp / PgDn 滚动。内置专家不能编辑或删除。冲突和失败保留草稿，不自动覆盖新内容。

本版先使用文字字段输入模型名称与能力组；能力组为 `read, write, web, commands, skill-install`。下拉选择、多选交互、光标跟随滚动等体验仍需结合试用调整。面板操作不发起模型轮次，但审计操作仍可在聊天的工具卡片区域出现；显示隔离尚待整理。Ink 客户端尚无同等管理表单。

## 隔离的真实界面演示

`tests/fixtures/expert-panel.actions` 驱动的不是另画的示意界面，而是终端宿主本身。演示需要独立 HOME、TMPDIR，以及含 `preview` 脚本模型的模型目录；不需要网络或密钥。

自动回归直接运行：

```sh
cargo test --locked --test expert_panel --no-fail-fast
```

它使用临时目录，通过真实键盘路径完成复制、保存授权、启用授权、拒绝删除与批准删除，并检查磁盘结果、授权事件和没有模型调用。绘制与编辑的定向检查：

```sh
cargo test --locked --bin lattice expert_ --no-fail-fast
```

这些检查不代替真人对布局、输入手感与授权说明的验收。

## 数据与协议

定义位于项目或个人目录下的 `.lattice/expert-definitions/<id>.json`。手工编辑仍可使用；定义存在不等于已经启用。主 agent 可通过 ListExperts、InspectExpert、SaveExpert、ActivateExpert、DeleteExpert 管理同一份数据。

前端通过独立的外部输入调用同一套管理部件与授权闸，不直接写定义。daemon 的 `manage_experts` 消息带 `stream`、`request`、`operation` 和 `arguments`；operation 为 `list / inspect / save / activate / delete`。结果通过 `experts.ui.result` 事件返回，request 用于关联本次界面操作。保存与启用使用现有授权通道；删除问题的事件类型为 `experts.authorization_requested`。

保存会先撤下旧版本的可用状态，再替换定义。如果中途失败，会报告已经改变的部分，不恢复旧授权、不在重启后重做。已接受的专家工作保留原来的执行快照；删除不取消这些工作，也不删除历史。
