# 原生发布产物

本文说明产物格式与编译方法，不表示已经发布了某个版本。[English](release-artifacts.md) · [发布准备](发布准备.md)

## 内容与身份

原生目标为 `x86_64-unknown-linux-gnu` 和 `aarch64-apple-darwin`。
每份 `lattice-vX.Y.Z-TARGET.tar.gz` 内有一个同名目录，包含：

- `lattice`，保留 `0755` 执行权限；
- `LICENSE`、`NOTICE`、`ASSET-ATTRIBUTION.md`；
- cargo-about 生成的 `THIRD-PARTY-LICENSES.html`，其中也包含 Lattice 自身许可证；
- `DEPENDENCIES.json`，自定义 Cargo 依赖图，**不是 SPDX 或 CycloneDX 标准 SBOM**；
- `SYSTEM-DEPENDENCIES.txt`，原生共享库检查结果；
- `BUILD-INFO.json`，编译记录。

依赖图可能包含构建依赖、开发依赖以及其他目标的依赖，不表示每个条目都链接进了这份可执行文件。
没有明确来源的本地路径依赖会被拒绝，不会错误地归到主仓库提交名下。素材署名与 Cargo 许可证报告分别保留。

编译记录包含来源提交、版本、目标、预览标记、编译时的编译器，以及清单、许可证生成配置和各打包文件的摘要。
它防止不同编译结果与报告被意外混装。**它本身是未签名的数据，不是独立的来源证明。**
正式分发还需要获批发布、校验和与工作流来源证明；仅凭版本字符串或这份记录，不能把本地产物变成正式发布。

## 在本机构建预览包

使用干净的工作区，包括未跟踪的源码文件；准备原生 Rust 工具链、Python 3.12，并将已校验的 `cargo-about 0.9.2` 放入 PATH。
在 macOS ARM64 上执行：

```sh
python3.12 scripts/build_release.py \
  --version "$(python3.12 -c 'import tomllib; print(tomllib.load(open("Cargo.toml", "rb"))["package"]["version"])')" \
  --commit "$(git rev-parse HEAD)" \
  --target aarch64-apple-darwin \
  --output target/release-preview \
  --preview
```

Linux x86-64 改用 `x86_64-unknown-linux-gnu`，并确保有 `ldd` 和 `readelf`。
交叉编译不属于这套方法的验证路径；该产物格式没有 Windows 或 Intel macOS 预编译目标。

脚本使用锁文件编译，重新生成署名和依赖报告，在每个生成步骤完成时记录摘要，再次核对工作区和编译器。
打包时拒绝不匹配的输入、链接、额外归档成员、错误的身份字段类型和不完整的依赖引用。
只有验证成功，最终压缩包文件名才会出现；不会替换已有压缩包。同一版本的另一份构建应使用新的输出目录。

脚本重新打开压缩包，将可执行文件解出，在临时主目录和少量显式环境变量下运行 `--version` 与 `--help`。
这避免加载平时的本机配置，但**不是文件系统或网络沙箱**，也没有验证付费模型或交互式引导。
分发检查可只读检查两种平台的数据，不在有发布写权限的任务中执行产物。

归档的排序、所有者、权限和时间戳受到控制；这不等于承诺更换编译器、SDK 或运行器后仍得到逐字节相同的二进制。
本地预览会使用正式版本号的输出格式，但它不是正式发布。

## 分发检查

`scripts/release_manifest.py` 要求两种平台的压缩包来自同一提交与同一阶段，然后生成 `SHA256SUMS` 和 `release-manifest.json`。
它拒绝额外文件，也不替换内容不同的既有元数据。工作流来源证明单独存放，避免形成自我引用的校验和。
发布时必须核对来源仓库、签署工作流和来源提交，不能只看“存在一个有效签名”。
发布集成与安装说明和本文的本机构建方法分开维护。
