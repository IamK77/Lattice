# 演示：agent 给自己造工具

一句话：你对 agent 说"给你自己造个工具"，它写代码、机器判卷、你点头、热装入、当场就用——全程走真机制，无一处魔法。

## 怎么跑

```
DEEPSEEK_API_KEY=... cargo run --example chat
you › 给你自己造一个工具：把文本转大写并数出词数，然后用它处理 "hello lattice world"
```

agent 会调用 `install_component`（自带工具），终端弹出确认框（部件名、它提供的工具、索要的作用面、体检与考卷已通过），你按 `y` 装入，它随即调用刚造好的工具给出结果。

## 底下真实发生的五关（无网络也能验证：`cargo test --test self_build`）

1. **自设计**：agent 写一段 stdlib Python（遵守契约六的每行一个 JSON 协议）+ 工具名片。boilerplate（自述、接线）由车间代劳。
2. **机器判卷**：`examine_tool_provider` 把它拉起放进一次性考场核心，喂标准考题，看流水判分——恰好一条合规完成、因果正确、无核心故障。**考不过原样返回问题清单**，agent 据此改代码重交（自调试）。
3. **人把关**：作用面确认框。agent 造的东西，装不装由用户点头（信任模型的正面出场）。
4. **热装入**：`Kernel::install` 对运行中的核心增量复检→注册信纸→加接线→拉起子进程，**对话不中断**。安装落一条决策类事件（带 agent 给的理由）。
5. **自使用 + 自查**：新工具进入下一轮工具清单；它干的活跨进程因果链完整；问"这工具哪来的"，agent 回查流水即可讲出全过程。

## 这场演示验收了什么

契约六（跨进程桥）、标准口型 + 符合性考卷、装配体检、工具作用面、信任确认、热装入、跨进程因果链、流水自查——几乎全部地基一次承重。

## 关键部件与代码

- `src/workshop.rs`：车间（写源码→建自述→跑考卷→热装入），host 侧库函数，不碰核心内部。
- `src/components/workshop_sink.rs`：车间插座（收安装请求、见证之，host 借其名注入结果）。
- `tests/self_build.rs`：免钥匙全流程回归（剧本模型演 agent），CI 常驻。
- `examples/chat.rs`：人机版，带 y/N 确认。
