# 契约一：事件信封

[契约导航](README.zh-CN.md) · [开发参考](../development/README.zh-CN.md)

一切发生的事都是事件。事件 = 信封（本契约规定的外层结构，所有事件相同）+ 信纸（payload，各事件类型自定义，核心不解读）。

机器可读正本：信封在 `schemas/envelope.json`，信纸在 `schemas/payloads/`；Rust 化身在 `src/contracts/event.rs`。`tests/schema_canon.rs` 把正本与实现双向钉住，并反向校验 Ink golden 文件里嵌的信封——JS 前端、Rust 类型、schema 三方单方漂移即红。

## 栏目

| 栏目 | 类型 | 谁填 | 说明 |
|---|---|---|---|
| `v` | number | 核心 | 信封格式版本号（现为 1）。读旧版自动升格，读新版拒绝——格式敢演进的前提 |
| `id` | string | 核心 | **流内**唯一编号，同流事件靠它互相指认；跨流寻址一律用"流号 + 事件号"二元组 |
| `seq` | number | 核心 | **流内**顺序号，落盘时分配，从 1 递增 |
| `stream` | string | 核心 | 归属：本事件所在的流（卷宗），由流水盖章 |
| `time` | string | 核心 | 落盘时刻，ISO 8601 |
| `type` | string | 部件 | 事件类型，带命名空间（见下） |
| `source` | string | 核心 | 产生此事件的部件实例名（由核心据发射口填写，部件无法冒名） |
| `causes` | string[] | 部件 | 因果：**共同**引发本事件的事件 id 列表（**同流内**）；根事件为空列表；多于一个即"合流"（如两个工具结果共同引发一次模型调用） |
| `origin` | {stream, event}（可选） | 部件 | 跨流弱引用："本流由某流某事件引发"，仅根事件上有意义 |
| `reason` | string（可选） | 部件 | 决策类事件必填：一句话解释为什么这么做 |
| `payload` | 任意可序列化数据 | 部件 | 信纸，本类型自定义 |

## 类型命名空间

`<归属>.<家族>.<名称>`，如 `core.model.call_completed`、`sched.task.split`。`core.*` 保留给核心；部件自带的信纸类型在部件自述中注册，装配体检保证同一类型只有一个注册者。

## 入口执法（流水追加时强制，不合格拒收）

1. `type` 必须已注册；
2. `causes` 中的每一个都必须指向流水中真实存在的事件——**因果链在物理上不可能断**；
3. 注册为决策类（`decision: true`）的类型必须带非空 `reason`；
4. **信纸校验**：类型注册时若附带 JSON Schema（正本在 `schemas/payloads/`），payload 不合格即拒收——第四道执法，护完信封护信内。

## 完成态原则

流水只记有因果意义的完整动作：一次完整的模型输出、一次完整的工具结果。"开始/结束"这类动作边界都是事件，照记；**这条原则排除的只有一样东西——流式小片段**（模型逐字吐出的那种），它们不是事件，走不落盘的实时通知旁路，只供界面显示。**失败不是例外，是一条普通的完成态事件**（`status: "error"`），照记不误。

## 归属：流

顶层容器是中性的**流**（stream，比喻：一事一卷宗）：一段因果自洽的事件序列，流内顺序号独立，自己开始、自己结束、可整体封存。"会话"是前端贴在流上的标签，"任务"是调度层贴的标签——核心一概不识这两个词。

- `causes` 只在流内成立：存在性校验与见证执法都以本流为界；回溯是祖先图的广度遍历，按流内序号降序输出（天然拓扑序：因永远早于果）；
- 跨流靠 `origin` 弱引用（流号 + 事件号）。核心不做跨流校验——审计链跨流可追，但该跳按构造即属"未验证"；
- 一条流水文件只属于一条流；重开时流号不符即拒绝。
