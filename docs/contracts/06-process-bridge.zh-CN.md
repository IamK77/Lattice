# 契约六：跨进程桥（v1）

[契约导航](README.zh-CN.md) · [开发参考](../development/README.zh-CN.md)

独立进程部件与核心的通信约定。**这份契约面向外语部件作者**——任何语言，只要会按行读写标准输入输出、会解析 JSON，就能实现一个部件。参考实现：`examples/components/hash_tool.py`（约 40 行、零依赖 Python）。

## 生命周期

1. 核心按自述里的 `entry` 拉起子进程并建立独立进程组。停止操作针对该组；自行脱离进程组的后代不在停止保证内，这不是进程沙箱。
2. 核心立刻从子进程的标准输入送入第一行——**握手**：
   `{"hello": {"v": 1, "instance": "实例名", "stream": "流号", "config": {…}}}`
   核心不等待回应；子进程可随时开始发言。
3. 此后双方各自按行收发（见下）。
4. 停止：先协议后信号——核心送 `{"stop": {}}` 并关闭子进程的标准输入；稍候对整个进程组发 SIGTERM；再稍候 SIGKILL。

## 核心 → 子进程（标准输入，每行一个 JSON）

| 行 | 含义 |
|---|---|
| `{"hello": …}` | 握手（仅一次，第一行） |
| `{"deliver": {"port": "口名", "event": {完整信封}}}` | 一次投递 |
| `{"cancel": {}}` | 当前投递被取消（打断/超时/policy）；尽快收尾 |
| `{"stop": {}}` | 请体面退出 |

## 子进程 → 核心（标准输出，每行一个 JSON）

| 行 | 含义 |
|---|---|
| `{"emit": {"port": "出口名", "type": "事件类型", "causes": […], "payload": {…}, "reason": …, "origin": …}}` | 发出一条事件草稿。**随时可发**（边缘适配件无需先被投递），经核心四道执法后入流水 |
| `{"processed": true}` | 每收到一次 deliver，处理完毕后必须回一行（含发完全部后续事件之后） |
| `{"notice": {…}}` | 不落盘的旁路通知（流式片段等） |

## 规则

- **信任**：子进程只能以自己的实例名发声（桥代为署名，冒充无门）；见证执法照常——causes 只能指向它收到过或自己发出过的事件。
- **活性**：自述可声明 `handleTimeoutMs`；超时即被取消，宽限期后按失联处理（对进程件=进程组强杀，核心记 component_crashed 后继续运行）。子进程无声消失同样被记为崩溃，因果指向其正在处理的事件。
- **前向兼容**：双方都必须忽略无法识别的行/字段。
- 传输格式 v1（每行一个 JSON）**永久支持**；更快的编码只能作为握手协商的升级。
