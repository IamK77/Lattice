# 契约五：标准口型（Port Profile）

给一类可替换部件定死"插座形状"：口的名字、方向、事件类型集合。同口型的部件互相可换——换部件只改说明书里的部件名，接线一根不动。权威定义在 `src/contracts/profile.rs`。

## 机制

- 部件在自述的 `implements` 栏声明"我实现了某口型"。
- **体检**做结构判卷：口型要求的每个口必须存在、方向一致、事件集合完全一致；多出来的口不管。声明不存在的口型、或口对不上，拒绝启动。
- **符合性考卷**（`src/conformance.rs`）做行为判卷：把候选部件装进真实核心、喂标准考题、看流水判分。机器判卷，不采信任何自我评估——这是"agent 一句话生成新部件"能够放心的根据。

## 已定口型

**model-adapter v1**：进口 `request` 收 `core.model.call_started`；出口 `result` 发 `core.model.call_completed`。考卷：喂一个合法请求，必须恰好回一条完成事件（错误完成也算完成——考的是契约形状，不是聪明），因果指回请求，全程无核心故障。scripted-model、anthropic-model、openai-model 均已通过（真脑断网应考：无钥匙路径）。**建议**同时带进口 `control` 收 `core.control.interrupted`：口型不强制，但官方脑全部带有——否则接了打断线的装配换脑会体检失败（换脑不应破坏装配）。

**policy v1**：进口 `review` 收工具请求；出口 `forward` 原样转发（实为带因果的重发出，经手留痕）；出口 `verdict` 发"工具执行结束"（拒绝时替执行器作答，主循环无需改动）。自己的拒绝决策信纸由各 policy 部件自带注册，不属于通用口型。**考卷已落地**（`examine_policy`，与立场无关：每个受审请求必须"转发"或"作答"二选一，拒绝须伴一条带原因的决策事件）。首个官方件 **effects-policy** 已过考：按工具在流水里申报的作用面判断（回查最近一次模型调用材料，从不认工具名），未申报按最危险处理；tests/policy.rs 证明纯工具放行、联网工具被拦且主循环零改动即恢复。

**context-manager v1**：进口 `ask` 收 `core.model.call_started`；出口 `forward` 原样或改写后转发（带因果的重发出，经手留痕）。考卷（`examine_context_manager`）：每个问话必须恰好转发一次、因果指回问话、**转发的指纹必须对得上转发的材料**、摘要件必须指明原件并携带便条文字；与裁剪立场无关（考形状不考品味）。首件 **context-gate** 已过考：窗口秤（型号档案 contextWindow × 比例，账本真实用量触发）+ 机械裁剪（旧工具结果→摘要件，最近几个保原文），压缩落决策事件（原因=哪杆秤、范围=压了谁）；无档案配置时惰性直通，拔出装配即回到裸清单。**v2 语义压实已并入同一部件**（config 开关 `condense`，需装配另接一台压缩模型实例：`condense`/`condensed` 一对口）：秤响时后台浓缩旧段为**四栏纪要**（Done/State/Open/Facts，缺栏拒收——固定字段使质量可检验）；纪要以部件自带事件 `context.summary` 落账复用（covers+text）；**次轮起被覆盖的原件由一枚"纪要摘要件"替换**（复用摘要件机制，适配件零改动）——入量回落、秤停，闭环收敛；再次浓缩为**滚动式**（上一份纪要作摘要件随材料进压缩调用，新纪要覆盖并集，替换只认最新一份）；本轮从不等待压缩（用户轮次零延迟）；是否在途**查账本判断**（重启不重复浓缩）；压缩调用带 `purpose: context.condense` 标记与主问话区分。配套安全阀 **ledger-tools**（tool-provider 口型已过考）：`recall_event` 凭事件编号取流水原文。

## 模型调用的三分（方言 · 门牌 · 档案）

调一次模型，实际上有三根互相独立的轴。绑死在一起会组合爆炸，所以契约把它们拆开——**Lattice 只定义抽象，三根轴上的具体实现都欢迎第三方补充**（与 policy 同一姿势：契约+考卷在官方，件可以是任何人的）：

1. **方言（怎么说话）= 部件**。一种请求/流式响应格式一个适配件部件，即上文 model-adapter 口型，过考卷即可上岗。官方参考件：anthropic-model、openai-model。
2. **门牌（寄到哪儿）= 标准配置键**。合规适配件应认这组配置：`model`（型号名）、`baseUrl`（端点）、`apiKeyEnv`（密钥所在的环境变量名——密钥本身永不入事件）、`maxTokens`、`system`。同一方言换供应商=只改配置（已实战验证：Anthropic 官方 ↔ DeepSeek 兼容端点零代码切换）。
3. **档案（收件人的脾气）= 纯数据文件**。一款型号一份档案，schema 正本在 `schemas/model_profile.json`：上下文窗口（上下文管理按比例预算的依据）、用量字段映射（各家缓存统计字段名不同，观察者聚合时靠档案对表）、开放的 quirks 扩展位。档案是数据不是代码，不需要考卷，过 schema 体检即可；参考档案在 `profiles/`（数值以供应商文档为准，使用者自行核对）。递交方式：装配说明书中模型实例的 config 可带 `"profile": {…}` 内联；适配件可暂不消费（向后兼容），需要该型号知识时再读。
