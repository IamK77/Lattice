# 契约三：部件自述

部件是自描述的分发单元。自述文件回答三个问题：我是谁、我和外界怎么交换事件、装上我之后默认怎么接线。机器可读正本在 `schemas/component_manifest.json`；Rust 化身在 `src/contracts/component.rs`（`ComponentManifest`），二者由 `tests/schema_canon.rs` 双向钉住（全部官方部件的自述实测过正本）。

## 栏目

| 栏目 | 说明 |
|---|---|
| `name` / `version` | 身份 |
| `runtime` | 形态：`inproc`（进程内加载）或 `process`（独立进程，任何语言的可执行文件） |
| `entry` | 入口：模块路径或可执行文件路径 |
| `inputs` / `outputs` | 事件口（见下） |
| `events` | 本部件自带的信纸类型注册（可选） |
| `defaultWiring` | 默认接线建议（可选）：安装器将其并入装配说明书，用户"下载即用" |
| `capabilities` | 整机作用面（EffectSurface，与工具 `effects` 共用同一词汇表：reads/writes/network/executes/reversible）；未申报按最危险处理。信任记录 = 内容指纹 + 授予的作用面 |
| `prompt` | 提示词片段（可选）：装配了本部件时应并入系统提示词的一段话——**部件自己教模型怎么用自己**。装了即注入、卸了即消失（内核收集，上下文关卡拼装）；装配说明书可按实例覆盖（config 的 `prompt` 字符串替换之、null 抑制之） |
| `tools` | 本部件提供的工具声明清单（可选，中立格式 `{name, description, parameters, effects}`）——**声明随实现走，不再手抄进装配配置**。内核收集并给每条盖上提供者实例标记（`provider` 字段，只入账不出网）；主循环把收集结果 offer 给模型；热装即时可见。体检把关：工具重名拒启（扇出路由按名认领，重名会双答）、声明了工具但没有任何接线能送达请求的实例拒启（模型会调进沉默、挂死一轮）。**常驻/待命分级**：装配时就在的工具=常驻（进 schema）；**热装的初次一律待命**（`installed` 标记）——不进 schema、不破供应商缓存，模型经常驻的转接工具 `use_deferred_tool`（声明恒定不变，正本 `deferred_dispatcher_decl`）调用之，主循环机械展开（同调用 id）；上下文关卡在**缓存反正冷的时刻**（上一轮 cacheRead=0）把待命晋升进 schema，落带原因的决策事件（action=promote），晋升状态从账上读、重启安全 |

## 口（Port）

口是部件与外界交换事件的端点，每个口声明自己涉及的事件类型：

- **输入口**："我接受哪些事件类型"。可声明 `["*"]` 表示照单全收（典型场景：审计观察者）。
- **输出口**："我会发出哪些事件类型"。**不允许 `"*"`**——不能承诺一切。运行时部件从某输出口只能发出该口声明过的类型。

## 形态与分散运行

`inproc` 与 `process` 对其余部件完全透明——边界只传信封 JSON，差别仅是核心的送信方式。**插件分发机制与分散运行机制是同一个机制**：用户下载的二进制部件跑在独立进程里，这本身就是分散运行。

## 安装流程

1. 下载部件（代码或二进制）；
2. 安装器读自述，校验信纸类型无冲突；
3. 把 `defaultWiring` 并入装配说明书（建议中的 `self` 替换为实际实例名）；
4. 重新体检、重启生效。全程用户只做了"下载"一个动作；开发者随时可打开说明书查看或手调这次安装改了哪几根线。
