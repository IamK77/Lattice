# 契约五：标准口型（Port Profile）

[契约导航](README.zh-CN.md) · [开发参考](../development/README.zh-CN.md)

给一类可替换部件定死"插座形状"：口的名字、方向、事件类型集合。同口型的部件互相可换——换部件只改说明书里的部件名，接线一根不动。权威定义在 `src/contracts/profile.rs`。

## 机制

- 部件在自述的 `implements` 栏声明"我实现了某口型"。
- **体检**做结构判卷：口型要求的每个口必须存在、方向一致、事件集合完全一致；多出来的口不管。声明不存在的口型、或口对不上，拒绝启动。
- **符合性考卷**（`src/conformance.rs`）做行为判卷：把候选部件装进真实核心、喂标准考题、看流水判分。机器判卷，不采信任何自我评估——这是"agent 一句话生成新部件"能够放心的根据。

## 已定口型

**model-adapter v1**：进口 `request` 收 `core.model.call_started`；出口 `result` 发 `core.model.call_completed`。考卷：喂一个合法请求，必须恰好回一条完成事件（错误完成也算完成——考的是契约形状，不是聪明），因果指回请求，全程无核心故障。scripted-model、anthropic-model、openai-model 均已通过（真脑断网应考：无钥匙路径）。**建议**同时带进口 `control` 收 `core.control.interrupted`：口型不强制，但官方脑全部带有——否则接了打断线的装配换脑会体检失败（换脑不应破坏装配）。

**policy v1**：进口 `review` 收工具请求；出口 `forward` 原样转发（实为带因果的重发出，经手留痕）；出口 `verdict` 发"工具执行结束"（拒绝时替执行器作答，主循环无需改动）。自己的拒绝决策信纸由各 policy 部件自带注册，不属于通用口型。**考卷已落地**（`examine_policy`，与立场无关：每个受审请求必须"转发"或"作答"二选一，拒绝须伴一条带原因的决策事件）。首个官方件 **effects-policy** 已过考：按工具在流水里申报的作用面判断（回查最近一次模型调用材料，从不认工具名），未申报按最危险处理；tests/policy.rs 证明纯工具放行、联网工具被拦且主循环零改动即恢复。

**context-manager v1**：进口 `ask` 收 `core.model.call_started`；出口 `forward` 原样或改写后转发（带因果的重发出，经手留痕）。基础考卷（`examine_context_manager`）使用不触发压缩等待的样例：问话恰好转发一次、因果指回问话、**转发的指纹必须对得上转发的材料**、摘要件必须指明原件并携带便条文字；与裁剪立场无关（考形状不考品味）。首件 **context-gate** 已通过这份考卷。该考卷不覆盖压缩生命周期：配置了异步准备过程的实现可以等待；准备失败或取消时必须明确结清原请求，不能既转发又给它第二份结局。额外的结局口及接线由具体实现声明，不改变 v1 必需口的结构。

### 随货上下文管理与回查（实现说明，不扩充口型）

`context-gate` 结合型号窗口、比例预算与账本用量，提供机械裁剪和可配置的模型压缩；压缩是带原因的视图变更，不改写流水原文。以下是当前实现策略，不是所有 context-manager 必须照做的通用要求：

- 文本纪要路径使用 `purpose: context.condense`，要求 Done/State/Open/Facts 四栏；Responses 原生压缩路径使用 `context.compact.responses`，接受原生结果，不要求四栏文字。不能把文本纪要格式当成所有压缩方式的共同契约。
- 启用语义压缩时，自动窗口压缩会暂存普通请求，保留原始材料，等替代结果成功且被采纳落账后再转发；不再让模型先使用机械回执继续工作。等待只发生在上下文闸，不阻塞事件投递。失败、取消、结果无效或暂停期间再次超预算时，原请求得到明确中断，不降级继续、不自动重试。未启用语义压缩的装配仍可单独使用机械裁剪。在途判断依据流水中的调用结局，打断也是结局。
- 压缩调用通过一条已落账的决策关联原请求，而不直接成为原请求的同类型子节点；压缩完成不能提前结清尚未转发的普通请求。成功转发的原因同时包含原请求和已采纳的摘要。重启仅清账和恢复观察，不重发等待请求。
- **自定义装配迁移**：使用新版随货闸并启用压缩时，须增加 `ctx.decision → ctx.handoff`、`ctx.summary → ctx.handoff` 两条自回接线，以及 `ctx.interrupted → loop.faults`；支持用户停止的装配还应将停止信号送到 `ctx.faults` 与压缩模型的 `control`。实例名按实际装配替换。默认装配已接好；旧的自定义装配不会被内核偷偷补线，遗漏自回接会使请求一直等待。
- 流水原文通过普通文件工具 `Read` 回查；环境提示提供当前流水路径及分卷定位方式。旧 `ledger-tools` / `recall_event` 不是当前随货工具入口。

实现分别见[上下文闸](../../src/components/context_gate.rs)、[显式压缩入口](../../src/components/context_gate_manual.rs)和[环境提示](../../src/components/environment.rs)；通用行为考卷在 [conformance.rs](../../src/conformance.rs)。

## 模型调用的三分（方言 · 门牌 · 档案）

调一次模型，实际上有三根互相独立的轴。绑死在一起会组合爆炸，所以契约把它们拆开——**Lattice 只定义抽象，三根轴上的具体实现都欢迎第三方补充**（与 policy 同一姿势：契约+考卷在官方，件可以是任何人的）：

1. **方言（怎么说话）= 部件职责**。适配件翻译请求与响应格式，遵守上文 model-adapter 口型；一个部件也可支持多种可选格式。官方参考件为 anthropic-model、openai-model。通过形状与行为考卷，不等于所有真实服务已经兼容。
2. **门牌（寄到哪儿）= 标准配置键**。合规适配件应认这组配置： `model`（型号名）、`baseUrl`（端点）、`apiKeyEnv`（密钥所在的环境变量名）、`maxTokens`、`system`。适配件配置传变量名而不是密钥值；这不是“密钥永不入事件”的保证，工具读取环境或文件仍可能把秘密带入流水。同一方言可以通过配置切换端点，但认证、能力和推理块接受规则仍须分别验证，不能从口型考卷推出供应商兼容。
3. **档案（收件人的脾气）= 纯数据文件**。型号档案的机器正本在 [model_profile.json](../../schemas/model_profile.json)：描述上下文窗口、用量字段映射与开放的 quirks 等字段。档案不是代码，Schema 检查其结构而不证明其中数值准确；[参考档案](../../profiles/)的能力与上限仍需对照所用服务核对。模型实例 config 可带 `"profile": {…}` 内联；适配件需要相应型号知识时消费它。
