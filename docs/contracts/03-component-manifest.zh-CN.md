# 契约三：部件自述

[契约导航](README.zh-CN.md) · [开发参考](../development.zh-CN.md)

部件是自描述的分发单元。自述文件回答三个问题：我是谁、我和外界怎么交换事件、装上我之后默认怎么接线。机器可读正本在 `schemas/component_manifest.json`；Rust 化身在 `src/contracts/component.rs`（`ComponentManifest`），二者由 `tests/schema_canon.rs` 双向钉住（全部官方部件的自述实测过正本）。

## 栏目

| 栏目 | 说明 |
|---|---|
| `name` / `version` | 身份 |
| `runtime` | 形态：`inproc`（进程内加载）或 `process`（独立进程，任何语言的可执行文件） |
| `entry` | 入口：模块路径或可执行文件路径 |
| `inputs` / `outputs` | 事件口（见下） |
| `events` | 本部件自带的信纸类型注册（可选） |
| `defaultWiring` | 默认接线建议（可选）：由安装器解析为实际接线；经过授权判断与安装检查后才可接入，不是下载即获得执行许可 |
| `capabilities` | 整机作用面（EffectSurface，与工具 `effects` 共用 reads/writes/network/executes/reversible）；未申报按最危险处理。随货信任闸按调用参数指纹与申报作用面匹配授权，不是对下载内容作指纹认证 |
| `prompt` | 提示词片段（可选）：装配了本部件时应并入系统提示词的一段话——**部件自己教模型怎么用自己**。装了即注入、卸了即消失（内核收集，上下文关卡拼装）；装配说明书可按实例覆盖（config 的 `prompt` 字符串替换之、null 抑制之） |
| `tools` | 本部件提供的工具声明清单（可选）。声明随实现走，不再手抄进装配配置。单条声明的 Schema 只要求 `name`；另有 `description`、`parameters`、`effects`、`async` 等字段，完整约束看机器正本。声明存在不代表它必须进入每一次模型请求的工具清单 |

## 口（Port）

口是部件与外界交换事件的端点，每个口声明自己涉及的事件类型：

- **输入口**："我接受哪些事件类型"。可声明 `["*"]` 表示照单全收（典型场景：审计观察者）。
- **输出口**："我会发出哪些事件类型"。**不允许 `"*"`**——不能承诺一切。运行时部件从某输出口只能发出该口声明过的类型。

## 形态与分散运行

`inproc` 与 `process` 对其余部件完全透明——边界只传信封 JSON，差别仅是核心的送信方式。**插件分发机制与分散运行机制是同一个机制**：用户下载的二进制部件跑在独立进程里，这本身就是分散运行。

## 当前随货工具的收集与暴露策略

以下是内核、主循环与上下文关卡的当前实现说明，不是 `tools` 字段额外的 Schema 约束。

内核收集声明并标记提供者实例 `provider`；这个内部标记不发送给供应商。体检拒绝工具重名，以及声明工具却没有工具请求接线的实例。请求按声明定向投递，未声明工具的关卡和观察者仍按接线接收。运行时请求没有接收者时，内核补 `interrupted` 结局，不伪造工具失败，也不依赖无关部件来回答。

成功热装后，声明进入工具目录；是否进入当前模型请求由材料策略决定：

- `deferTools` 配置中的工具持续待命，不随冷缓存晋升。标准装配中的内置 `Desktop` 就是这种情况，因此“启动时已有”不等于“常驻模型清单”。
- `FindTools` 可查配置为待命的工具和热装工具，包括已经晋升的热装工具；`UseDeferredTool` 由主循环按原调用标识机械展开。转接声明内容固定，但仅在本次仍有隐藏工具时加入模型清单。
- 热装工具带 `installed` 标记。未被配置为长期待命的工具，在配置了 `profile.contextWindow` 且尚未晋升时暂缓进入清单；没有该配置便不作此暂缓。
- 最近一次主模型调用的缓存读取量按当前实现算为 0 时，可以晋升这批临时待命工具。没有主调用记录、计数缺失或无效也按 0 处理，所以可能首次整理材料就晋升，不能承诺至少隐藏一轮。晋升写入带原因的 `action=promote` 决策，状态从流水恢复。

实现定位：[声明与转接入口](../../src/contracts/component.rs)、[工具目录](../../src/components/tool_catalog.rs)、[上下文关卡](../../src/components/context_gate.rs)。

## 安装流程

这里描述随货安装服务，不要求所有第三方安装器采用相同界面：

1. 准备部件代码或二进制及自述，接受现有授权路径的判断。可复用授权或当前权限可能已覆盖本次操作，不保证每次都弹确认。
2. 解析自述、声明与接线建议，检查类型、实例、口及安装条件；`self` 等建议端点须解析为实际实例。
3. 通过检查后在运行中的内核接入，无需靠重启才首次生效。
4. 另行把安装增补持久化，以便后续启动恢复。即时接入与写入增补不是一个提交点；持久化失败会报告，不能把本次运行已接入理解为保证跨重启保留。

随货信任按规范化调用参数的指纹和申报作用面判断，不读取 URL 或路径内容来产生内容指纹。后来同一地址的内容改变，不自动重新授权；永久信任的撤销仍由用户手动管理。作用面是部件自述，不是沙箱。

安装增补与产品基线分开，卸载只能移除增补中的实例，不能借此拆掉基础装配。详见[产品装配配置](../assembly-configuration.zh-CN.md)、[信任实现](../../src/components/trust_policy.rs)和[安装服务](../../src/workshop.rs)。
