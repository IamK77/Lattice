# 装配配置：完整基线与安装增补

## 两份文件各管一件事

- **完整基线**由用户选择，决定基础实例与全部接线。环境变量 `LATTICE_ASSEMBLY` 未设或为空时用内置基线；指定路径后，文件缺失、格式错误、部件冲突、体检失败或无人回答的授权关卡都会拒绝启动，不悄悄降级。
- **安装增补**默认是 `~/.lattice/assembly.json`，由安装和卸载服务维护；`LATTICE_OVERLAY` 可改路径，空值禁用。它仍然只增加，不覆盖基础同名实例，也不删除基础接线。增补合并失败沿用原来的整份跳过并告警行为。

两份文件不可共用路径。完整基线中的实例不是安装所得，不能被安装工具卸载。这里没有赋予安装工具修改完整基线的能力；这也不是对能读写任意文件的工具提供沙箱隔离。

## 从真实基线开始修改

```sh
lattice assembly > baseline.json
LATTICE_ASSEMBLY="$PWD/baseline.json" lattice
```

第一条只输出 JSON，不启动内核或调用模型。输出不含安装增补，避免把可卸载实例固化成基础实例。若已选择自定义基线，输出的是它解析后的基线。导出内容含配置与提示词，外来部件的配置可能含敏感值，应妥善保存，不能把整份文件当作可公开的无秘密样例。

文档形状如下，实例和接线请从导出结果修改，不要把下面的省略示意当作可启动文件：

```json
{
  "runtimeSlots": ["model", "cmodel", "ctx"],
  "components": [],
  "assembly": {
    "instances": {},
    "wires": []
  }
}
```

`components` 是额外部件自述清单，已有内置部件不重复定义；新名字不能与内置或同份文档中的其他部件重名。进程内实现仍须由宿主提供工厂，写一个自述不会凭空产生可执行代码。进程外实现使用自述中的入口和现有逐行 JSON 桥。

`assembly` 遵守 `schemas/assembly_manifest.json`；每份额外自述遵守 `schemas/component_manifest.json`；外层形状正本是 `schemas/product_assembly.json`。除下述运行时位置外，缺少的实例不会补回，缺少的线不会偷偷补上。

## 为什么显式列出三个运行时位置

完整接线图不等于把会话运行时状态冻在导出时刻。标准聊天宿主已有模型目录、思考设置和支线恢复；若随后把文件中的旧模型配置原样覆盖回来，界面会显示新模型，实际却用旧模型。

因此当前产品文档必须声明 `runtimeSlots` 为 `model`、`cmodel`、`ctx`，并在实例表保留这三处。装配员以当前模型选择、思考设置和上下文配置填入它们的实例声明，**不补它们的接线**。导出中的这三份声明用于查看当前解析值，持久改模型和上下文参数仍用已有模型配置入口；直接改这三份快照不会覆盖运行时选择。

其他实例与接线可以增删和替换，所需口型仍由体检检查。现有聊天前端还约定 `ui` 等角色和入口，不是任意图的通用工作流界面。要替换这些宿主角色、取消模型循环或自建前端，使用核心的 `AssemblyManifest` 与宿主 API；核心不认识上述三个名字。专家是另外的装配模板，不继承后再裁剪用户会话的完整基线。

## 在工具线上插入必经关卡

假设原线为 `loop.run → trust.review`：

1. 在完整基线添加关卡实例，例如 `extra-gate`。
2. 删除原来的直连线。
3. 添加 `loop.run → extra-gate.review`、`extra-gate.forward → trust.review`，并按该部件的自述接好拒绝结果等其他输出。
4. 重新启动一个会话验收，沿流水检查请求是否真的经过新关卡。

只在安装增补里添加这两条线而不删除原线，不能得到必经关卡。程序不猜“加上新线是不是想删旧线”；完整基线必须把意图写清楚。
