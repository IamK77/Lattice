# 桌面操作

`Desktop` 让 agent 看指定应用窗口，并向那个窗口点击、输入、按键、滚动和拖动。这属于 computer use，但不是任何模型厂商的专用 API。标准装配默认提供它，没有隐藏的启用开关；和 Browser 一样，完整参数通过 `FindTools` 按需发现，而不是常驻每轮提示。使用截图判断界面需要能读图的模型。

## 安装与系统许可

当前随货适配件支持 macOS，使用独立的 Cua Driver 子进程。驱动并不打包进 Lattice 二进制；没有驱动时，调用明确报安装缺失，普通聊天仍可启动。

当前适配件面向 Cua Driver 0.26.1 的 MCP 接口，默认入口为 `~/.lattice/drivers/desktop`，可链接到独立安装目录中的 `CuaDriver.app/Contents/MacOS/cua-driver`。配置 `executable` 或环境变量 `LATTICE_DESKTOP_DRIVER` 可指定其他安装位置；这不是允许任意程序充当驱动的协议承诺。其他版本需要单独验证兼容性，不自动承诺支持。

从驱动官方发布取得适合本机的档案，核对版本、摘要、归档路径与应用签名，再设置入口。新后端可以实现 `DesktopDriver`，或作为普通工具部件使用 Lattice 的进程外 JSON 行契约，无需修改核心事件。

驱动由 Lattice 按需启动，使用独立临时 HOME、清理后的环境、关闭遥测与更新检查，不继承模型密钥。以 `mcp --direct` 运行，不连接共享的桌面守护进程。这个方式的 macOS 权限归属于启动 Lattice 的宿主，而不是另一个常驻服务。请按实际使用的终端或宿主应用配置权限。

用户需要在“系统设置 → 隐私与安全性”里给该宿主授予：

- **屏幕录制**（系统版本也可能显示“屏幕与系统音频录制”）。
- **辅助功能**，用于发送输入。

若系统要求退出重开宿主，请先结束当前会话再重开；不要在承载当前会话时让 agent 重启终端。驱动不主动请求、也不绕过这两项权限。截图和输入前会检查权限，缺失时在发送输入前返回原因。

## 使用方式

先列目标，再观察，最后输入；不要从别的窗口截图猜坐标。

```json
{"operation":"list"}
{"operation":"observe","target":"从列表取得的 id"}
{"operation":"act","target":"同一个 id","actions":[{"type":"click","x":120,"y":80},{"type":"type","text":"literal text"}]}
{"operation":"close"}
```

- `list` 返回不透明标识、应用名和标题；不开放原生进程编号或供应商工具名。
- `observe` 返回 PNG 文档引用与像素宽高；模型适配件读取真实图片。坐标从截图左上角开始，不能等于宽或高。
- `act` 每批最多八项，可用 `click`、`type`、`key`、`scroll`、`drag`。点击次数最多三次，滚动量为一至五十。`key` 支持字母数字及常用编辑、方向键，修饰键为 `command/control/shift/option`。`delete` 表示向前删除，`backspace` 表示向后删除。
- 输入采取明确的前台投递：驱动暂时把目标放到前面，完成后恢复先前前台应用；不是失败后偷偷升级投递方式。
- 批次完成后尽力返回新截图；观察失败单独报告。`completedActions` 是结束的驱动操作数，不保证点击真的实现了预期界面效果；`uncertainAction` 指向可能只执行了一部分的那一项，不能整批重试。
- 遇到不确定的输入结果，当前驱动会拒绝继续输入；显式 `close` 后需重新列举和观察，而不是自动重放。
- `close` 只释放驱动，不退出被操作的应用。重开流水同样不会重放输入。

正常有界操作不另加逐窗口、逐批审批。窗口仍是外部内容，网页或窗口内的指示不能授权泄密、发送消息或破坏数据；这些行为仍应服从用户授权和既有工具规则。截图会留在流水旁，并发送给当前模型，不应让秘密进入画面。

## 保护与边界

自动排除当前进程及其宿主祖先；标准装配还通过 `hostProtection.applications` 排除终端、代理和系统控制类应用。这份附加清单是宿主配置，不是供应商内置策略。更换网络代理或承载会话的应用时，应同时维护宿主配置。

窗口标题变化不影响目标，进程出生信息、窗口编号或应用身份变化则拒绝复用旧目标；窗口尺寸变化要求重新观察。它防止明显的选错窗口和过期坐标，不承诺隔离恶意应用，也不能证明应用点击后的外部业务行为可逆。

只有持久流水才能观察和输入：图片按内容取名，落为 PNG 文件，不将几兆 base64 塞进单行账本。发送模型前同时核对内容身份、字节数和 PNG 像素；图片被改坏时拒绝发送，不能静默丢图。适配覆盖 Anthropic、Chat Completions 和 Responses，具体模型本身仍须支持视觉输入。

## 验证

普通回归使用可替换的本地假驱动和假 MCP 进程，不调用模型端点，也不需要桌面权限：

```sh
cargo test --lib desktop
cargo test --test desktop --test images
cargo test --test preset the_standard_assembly_starts_and_runs_a_turn
```

真机验收为明确标记的独立测试，不进入默认测试运行：

```sh
cargo test --test desktop_live -- --ignored --nocapture
```

它先检查宿主权限，再编译并启动仓库里的 AppKit 测试窗口，只点击和输入这一个临时窗口，核对窗口回报的原文与截图变化，最后关闭自己创建的进程。不读已有用户窗口内容，不联网、不调用模型；缺权限是失败，不能伪装成通过。

这项测试覆盖专用窗口的发现、截图、点击与文字输入；通过它不代表所有应用、滚动、拖动、快捷键或模型自主操作循环都已经验证。每台机器仍需独立检查驱动兼容性和系统权限。
