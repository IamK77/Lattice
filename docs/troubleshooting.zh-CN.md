# 故障排查

[English](troubleshooting.md) · [安装与升级](installation.zh-CN.md) · [支持渠道](../SUPPORT.md)

从最小的观察开始。不要删掉 `~/.lattice` 来重置，不要覆盖已有模型目录，不要导出全部环境变量，也不要上传整本流水。

## 执行了旧程序，或平台不匹配

比较 `command -v lattice`、命令链接和 `lattice --version`。优化过的开发构建仍不是正式发布。包无法启动时，记录系统和架构，对照[实测平台表](installation.zh-CN.md)。旧系统缺少动态库或符号，不能靠给归档改名或跳过验证解决。查看 `SYSTEM-DEPENDENCIES.txt`；没有承诺旧系统兼容，应换用受支持环境，或审阅后从源码构建。

Linux 源码构建需要 OpenSSL 开发头文件和 `pkg-config`，只有运行库不够。浏览器、桌面驱动、语言服务和 Ink 客户端另有前提，见[第一次对话](getting-started.zh-CN.md)。下载的程序无法执行时，先验证来源、检查准确诊断，不要直接关闭操作系统安全检查。

## 没有可用模型，或连到了意外的提供方

检查目录路径与变量**名称**，不要输出密钥值。`LATTICE_MODELS` 指定模型目录，空值禁用默认目录；编辑时保留已有条目。

`LATTICE_ADAPTER`、`LATTICE_MODEL`、`LATTICE_BASE_URL`、`LATTICE_API_KEY_ENV` 中任意一个存在，都会选择环境配置路线，不是和已保存模型逐字段合并。如果想用目录与保存的选择，应从本次启动中移除这四项覆盖；否则完整配置环境路线。

没有这些覆盖时，先选可达的保存模型，再选目录中首个有凭证的条目。保存条目仍在但凭证消失时，会警告后回退；条目已被删除时安静回退。程序不附送账号或免费默认模型。发送敏感工作之前，用 `/model` 确认提供方。

提供方拒绝请求时，核对端点根地址、型号、上限、协议和设置。完全省略思考参数要这样启动：

```bash
LATTICE_THINKING= "$LATTICE_BIN"
```

不设置变量会使用保存的偏好，否则用 high；`off` 则明确发送关闭设置，两者都不等于省略参数。

`LATTICE_SCRIPTED` 按变量是否存在判断。`LATTICE_SCRIPTED=0` 仍会启用测试模式，回到真实模型须移除变量。脚本模式不是沙箱，仍可能加载配置中的装配增补。

## 找不到对话，或历史似乎损坏

恢复按当前项目目录筛选。旧记录没有项目标识时仍对所有项目可见；先确认从哪个项目目录启动，再判断是否丢失。

新的终端对话保存在 `~/.lattice/ledgers/` 下的目录中，旧 `tui/`、`chat/` 仍会被查找；daemon 流则使用 `~/.lattice/streams/`。保留历史引用的文档和附件目录。`LATTICE_HOME` 不是通用的数据根目录开关，实际路径使用 `HOME` 和各项独立覆盖变量。

只想观察一小段原文且不加载凭证、不写入时，使用 `lattice --recover PATH --offset BYTES --bytes COUNT`。分卷流水可用 `lattice --verify-ledger DIRECTORY` 做完整只读校验。它们的输出也可能含敏感内容，应在本地检查后再分享。正常恢复对话不是只读诊断，会修复未完成尾部并结清悬挂调用。

不要把 `compact`、`tidy`、`--migrate-ledger` 当成普通检查；它们可能写入、移动或删除数据。迁移要求源文件离线，并保留原文件；树外附件引用还需单独照顾。改变数据格式前先读[安装与回退](installation.zh-CN.md)。

## 工具或扩展表现异常

工作目录和工具自述的作用面不是操作系统沙箱。中断后先检查实际结果，再决定是否重试，因为操作可能已经部分生效。完整装配基线与安装增补要分开检查；`assembly.json` 通常是增补，不是完整基线。装配导出可能包含敏感配置和提示词，不要未经检查就分享。

缺少语言服务会报错，不会自动安装。浏览器需要 Chrome/Chromium；桌面需要外部驱动和 macOS 权限。CLI 启动成功不表示这些集成也已验证。

## 适合提供给维护者的信息

提供准确构建身份、系统与架构、安装来源、最小复现、预期与实际行为，以及一小段检查过的错误。发布验证失败时，附版本或预演运行身份，以及具体哪一步失败，不附凭证。敏感安全问题走[私密报告渠道](../SECURITY.md)，不要直接发公开 issue。
