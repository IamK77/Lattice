# 依赖与持续集成维护

[English](supply-chain.md)

## 检查什么

候选代码的 CI 只有仓库读取权限，检出后不保留 Git 凭据。Actions 固定到完整提交号；固定输入不等于独立审计过该输入。

- Linux：格式、无警告的 Clippy、Rust 测试套件与 heartbeat 示例。
- macOS ARM64：程序入口、版本、社区资料及契约检查，以及关闭默认功能后的库构建。不表示每个外部集成都测过 macOS。
- Rust 兼容性：单独检查声明的最低工具链，主要 Rust 检查另外运行当前稳定版。
- 前端：从已提交的锁文件执行 `npm ci --ignore-scripts`，运行 Node 测试，并以脚本模型做真实客户端与后台进程的跨语言冒烟，不使用付费模型凭证。
- Rust 依赖：cargo-deny 检查锁定依赖图的已知通告、可接受许可证及来源，拒绝未知注册源和 Git 源。明确设置 `unsound = "all"`、`unmaintained = "all"`，覆盖间接依赖；启用全部 Cargo 功能并不会扩大这两类通告的检查范围。
- 前端生产依赖：npm audit 拒绝高危和严重问题，较低级别仍会显示在输出里；不承诺零风险。
- 工作流：actionlint 检查语法，关闭其可选外部 shellcheck、pyflakes 联动；它不代替脚本测试。

`Cargo.lock` 与 `clients/ink/package-lock.json` 都是需要审阅的源码输入。锁定安装失败时，不得悄悄改用非锁定安装。不要把凭证或私有注册源写进锁文件。

## 依赖更新

Dependabot 每周为 Cargo、npm 和 Actions 提交分组更新，目标都是 `develop`。这些只是提案，仍需审阅和检查通过，不构成合并或发布授权。`dependabot/` 分支是一个有限例外：只有同仓库、由 `dependabot[bot]` 创建的 PR 能使用，且不得直接进入 `main`；仅有相似分支名不够。

更新 Action 时，完整提交号与版本注释一起核对；同时审阅新增权限、安装脚本、来源、许可证、测试与发布逻辑，而不只看版本数字。Dependabot 不会更新 Shell 命令里任意下载链接或工具版本；actionlint、cargo-deny 及后续打包工具仍需明确维护。

通告数据库会变化，锁文件不变也可能从绿变红。解决问题，或者留下精确到具体通告、带理由、负责人及复查日期的例外；不能为了恢复绿色而关闭整类通告、许可证或来源检查。

当前维护例外是 syntect 引入的 `bincode 1.3.3`（RUSTSEC-2025-0141）和 `yaml-rust 0.4.5`（RUSTSEC-2024-0320）。对应上游迁移仍是待办，不是已解决问题。[例外记录](../../advisory-exceptions.json) 写明维护者，并于 2026 年 10 月 28 日到期。CI 会拒绝到期例外、已变化的依赖版本，以及没有对应记录的忽略项；不能不复查上游状态、不给理由就延长日期。

## 边界

许可证允许列表是在依赖的授权选项中选择可接受项，不是给依赖重新授权，也不代替法律判断。分发副本时，应同时保留适用的 NOTICE 和素材来源说明。

检查通过不表示具备沙箱、付费模型兼容性、代码签名、可重复构建或没有漏洞。分支保护是 GitHub 上的设置，必须另行核实，不能仅凭 YAML 宣称已生效。长期分支约定见[协作流程](workflow.zh-CN.md)，私密漏洞报告见[Security](../../SECURITY.md)。
